# RSH 框架迁移到 Ascend 910B：测试实验设计 v2

日期：2026-10-17。状态：实验设计完成；尚未实现本轮完整原型、尚未执行本轮新 NPU 实验。本文整合并取代先前首轮方案中的实验安排。

## 1. 目标、范围和待回答问题

先判断 RSH 的主体流程迁移到 910B 是否有性能潜力：共享列候选 → 结构重排 → RSH 行分流与滑动成窗 → 列压紧 → Cube/Vector 执行。此阶段不承诺新增算法贡献。

本轮不做超长行拆分，不做新的跨组交换或联合分组算法，不精细研究阈值和候选特征。阈值只是起步值，效果不佳时允许小范围复测。

依次回答：

1. 同一 NPU 后端上，前置重排是否改善全 Cube 执行？
2. 在相同行序上加入 RSH 的分流和滑动成窗，是否改善完整 SpMM？
3. 暂时忽略尾窗时，主体是否已体现收益，是否值得继续补齐尾部设计？
4. 默认参数效果不佳，是否只是阈值选择不合适？
5. 内核收益能否在计入 B 准备和一次性预处理后保留？

## 2. 固定实现与起步参数

### 2.1 平台和公共后端

- 目标为用户已确认的 910B。运行前记录实际子型号、驱动、CANN、核数和内存；旧构建脚本写死 Ascend910B2，须与实机核对。
- 复用已有 ACL 计时、数据读取与 Cube 工程；旧方案是 AIC-only，不能视为已经实现本轮 AIV 残余或混合后端。
- A/B 为 FP16，FP32 累加、FP32 输出；所有方法采用相同精度和数值参考。
- 固定 A 结构和值；B 驻留设备，每次调用读取当前 B。使用至少两组不同 B 交替检查，不能跨调用复用过期 Bpack。
- Cube 组按列并集压紧并与对应 B 行相乘，块尺寸和布局按实际 910B 接口适配；AIV 执行 CSR 输出行任务。分流互斥，同一输出片段由一个任务负责。
- 先串行跑通正确性，再建立两路并发。不能用未实现并发的版本对并发收益作结论。整个矩阵的窗口按任务列表批处理，不把每个小窗口单独一次主机启动作为最终性能实现。

### 2.2 结构流程

- W=16，是行窗口高度；特征宽度另记 N。
- 列倒排索引生成共享列候选 C(r)，排除自身并去重；低频列优先，候选预算 256。候选截断明确记录，不称精确全局近邻。
- weighted Jaccard 的 alpha=1；kNN 的 k=16，不足则全取。无向邻居关系取并集，用 1-sim 求最小生成森林，按确定顺序 DFS；固定行窗内做一轮 2-opt，孤立行置末尾。
- tau_nnz=4、tau_inc=2 为自行设定的默认值。保留 RSH Algorithm 1 的条件方向：Delta<tau_inc 且 nnz(r)<=tau_nnz 时移出首行并滑一行；否则接受整个 W 行窗口并跳 W 行。
- 扫描过程中动态判断尾部，不预先按 n mod W 删除行；长行完整保留，不拆分。
- 对每个 A、阈值配置，预处理固定三类非空工作：G=完整 Cube 窗口，S=判据移出的非尾残余行，T=动态尾行。单独记录空行，保证每个原始行被唯一覆盖或明确为空输出。

阈值、候选预算、不连通图处理和尾窗协议属于移植补齐；不冒称作者原始实现。公开 v1 只明确行窗内尾块的几何补齐，没有明确不足 W 行的尾行窗处理。

## 3. 六个主版本与配对主体对照

| ID | 结构与执行 | 尾部处理 | 输出范围 |
|---|---|---|---|
| V0 | 原始行任务，全 AIV CSR | AIV | 完整 |
| V1 | 原始行序，固定 W 行窗，列压紧，全 Cube | 补零至 W 行走 Cube | 完整 |
| V2 | RSH 重排行序，固定 W 行窗，列压紧，全 Cube | 补零至 W 行走 Cube | 完整 |
| H-V | RSH 重排与 Algorithm 1，G 走 Cube，S 走 AIV | T 走 AIV | 完整 |
| H-C | 与 H-V 完全相同的 G/S/T | T 补零至 W 行走 Cube | 完整 |
| H-Skip | 与 H-V 完全相同的 G/S/T | 不执行 T | 部分输出诊断 |

H-V/H-C/H-Skip 内部冻结行序和 G/S/T，只改变 T 的执行方式，不能重新重排或分流。H-Skip 仍计算 S，不能将它简化为只测 Cube 路径。

### 3.1 完整任务的对比

- V2 对 V1：前置重排的整体影响。
- H-V/H-C 对 V2：RSH 分流及随之改变成窗的联合影响，不能仅归因为某个路由特征。
- H-V 对 H-C：尾部执行方式的总体影响，包含负载和启动变化，不等于纯尾窗计算成本。
- 所有完整混合版本对 V0：相对于 Vector 方案的实际收益。

V0/V1/V2 是同后端的机制基线，不代表所有已有 NPU 实现的最强性能。整体迁移结果有潜力后，再加入实际可运行的官方库或 Neutron-style 同设备对照；未取得作者优化内核时不称完整复现。不能仅凭超越本轮受控基线声称超越 Neutron 或达到论文发表条件。

### 3.2 H-Skip 的两个口径

令 R 为全部原始行去掉 T，按原始行号标识，通常不是原矩阵连续前缀。

**主体同工作量对照：**增加 V0-R、V2-R，真实只计算相同 R。

- V0-R 用同一 AIV 后端计算保留行。
- V2-R 保留完整输入上已生成的 RSH 行序，限制到 R 后重新构造该基线自己的固定窗口与布局；不重新运行相似度重排算法。
- H-Skip 冻结原 G/S，不重组主体。基线可以为同一 R 采用其正常执行布局，不强制继承 H-Skip 的 Cube/Vector 标签。
- 保留 A 的完整列空间和 B，不删除 B 中与 T 同编号的行；保留输出行仍可能访问它们。
- 正确性只核对 C[R,:]=A[R,:]B；T 标为未计算，不填零冒充完整结果。

**乐观参考：**可以报告完整基线时间除以 H-Skip 时间，标为“忽略尾窗成本的乐观估计”。它不是相同输出任务的加速，也不是严格数学上限，不能混入完整任务的加速汇总。

每组保存 T 的原始行标识、行数/NNZ占比。阈值变化时 T 可能变化，各 H-Skip 必须配对应的 R；不能靠丢掉更多昂贵行选出更优阈值。若 T 为空可复用等价记录并明确标注，无须重复测量同一执行计划。

## 4. 数据与分阶段测试规模

### 4.1 数据

复用本地八张 CSR：ca-HepTh、email-Enron、bcsstk17、ns3Da、bcsstk38、thermal1、cit-HepTh、web-NotreDame。

- 三张开发矩阵：ca-HepTh、email-Enron、bcsstk17，用于打通与必要阈值校准。
- 其余五张用于冻结参数后的评估。八张均接触过历史结构分析，不能称为完全未见数据；旧配置中的 dev/test 标签不代表本轮严格隔离。
- 沿用原结构、固定随机种子的有符号 FP16 值；原配置说明它们不是原科学计算数值。每种方法必须使用同一 A/B。初轮结论对应这些结构和统一数值分布。
- N={16,64,256} 为性能点；N=33 先作为非对齐正确性检查，不立即扩展性能扫参。

### 4.2 顺序与规模

| 阶段 | 运行内容 | 主要输出与推进条件 |
|---|---|---|
| 0. 正确性与环境 | 小矩阵、官方/现有算子编译链、两路后端和完整计时链 | 通过覆盖检查和数值检查；失败先修复，不采纳失败性能记录 |

| 2. 默认参数评估 | 8 矩阵 × 3 个 N × 6 主版本，144 个配置，含阶段 1 的对应点 | 其中 120 个完整输出点、24 个 Skip 诊断点；统一记录默认效果 |

第一轮不扩展 W、k、候选特征和长行拆分的参数研究；它们保持固定，减少收益归因混淆。

## 5. 阈值复测规则

触发条件：默认完整混合版本没有超过最强同后端对照，或两路明显失衡、实际补齐量偏大。不以默认 (4,2) 一次失败否定框架。

小网格：tau_nnz∈{2,4,8}、tau_inc∈{1,2,4}，共 9 组。

- 使用完整任务时间选择参数，禁止使用 H-Skip 排名调参。
- 默认固定 H-V 做网格；若开发阶段 H-C 在三独立重复中的三矩阵聚合延迟均稳定优于 H-V，则先固定 H-C，再做相同网格。一次只校准阈值，不把尾策略也全部展开。
- 首先在 N=64 做定向校准；若默认仅在另一宽度失效，则改选该宽度，若 16/256 都单独失效，则选择默认完整混合相对 V2 几何平均加速更低的一档，同分优先 16。只在选定一档宽度上展开网格。
- 以三开发矩阵在该校准宽度的完整时间几何均值选一套公共配置；提升未超过空对照波动或重复方向不稳定时保留默认。近似并列优先默认，其次按固定参数顺序选择，避免事后随意挑选。
- 参数冻结后评估其余五张。逐矩阵/逐 N 的已测网格内最优另标探索性诊断，不充当自动取得的默认性能。
- 改阈值后重新生成 G/S/T；若补做尾部对照，只在该配置内部冻结新计划。
- 记录搜索与计划重建时间；如实际流程包含逐矩阵自动校准，该成本计入使用总成本。

## 6. 正确性和计时协议

### 6.1 正确性

- 输入统一排序、归并重复列，并在所有方法间固定同一量化结果；支持非单位值和正负值。
- 用同一 FP16 输入提升到 FP64 计算 CPU 参考，逐项检查全部真实输出；初轮沿用统一 atol=1e-2、rtol=1e-2，并报告最大绝对误差及相对 L2 误差。不得为某个版本单独放宽阈值。
- 检查原始行映射唯一、非零工作不丢不重；空行输出为零。H-Skip 明确缩小验证范围，完整版本必须验证全部行。
- 覆盖：全零、空行、M<W、M=W、M=W+1、尾部不同长度、n 可被 W 整除但剔行后产生尾部、N=33、无共享列、相同列集合、单条长行但不拆分、重复调用更换 B。

### 6.2 计时

- 公共后端预分配 workspace，避免只对某变体在计时中分配内存。每次调用必需的置零、B 准备、布局转换、同步和输出恢复仍计入。
- 主指标为 B 已在设备、当前 B 尚未准备成 Bpack 到结果就绪的完整调用延迟；以同步 API 墙钟配对比较，设备事件/profiler 用于辅助分解，明确计时边界。
- 单独记录 CPU 重排、分流、格式准备、计划传输和首次调用时间。编译和下载时间不混入稳态算子延迟。
- 至少 10 次预热、30 次采样、3 个独立进程；同任务方法按固定种子随机交错，记录中位数、IQR和配对结果。先选小规模点增加“同一实现两个标签”的空对照，确定实际噪声。
- 运行期间避免其他负载干扰。三独立重复方向一致且收益超过空对照波动才记为稳定收益；不使用单次最快值判定。
- 诊断 AIC/AIV、B 准备的独立计时可能改变流水，不能简单相加替代真实完整调用时间，也不能仅凭两个算子名称宣称已并发。

## 7. 指标、结果表和结论口径

### 7.1 结构分流表

每个矩阵/参数记录：原始 M/K/NNZ、G/S/T 的行数与非零占比、跳过的零首行数、完整窗口数量、列并集分布、实际物理块数、补齐量、B 准备规模、候选截断比例、结构计划大小。窗口内零行保留其调度归属并额外标记为空，不重复加到行数总和中。尾部行数与 NNZ 占比必须同时报告。

### 7.2 完整任务性能表

V0/V1/V2/H-V/H-C 分列：完整调用中位数/IQR、相对 V0 和 V2 的加速、准备时间、首次调用、workspace、数值误差。只汇总相同矩阵/N 的完整输出结果。

报告复用次数 q={1,10,100,1000}：

`T_total(q)=T_prepare + T_first + (q-1)*T_steady`，q>=1。

T_prepare 包括该方法必须的 CPU 结构准备、格式准备和首次计划传输，不包含已经在 T_first 中计入的计算；T_first 是计划就绪后的首次完整调用，T_steady 是稳态完整调用。每次 B 更新的 Bpack 都属于相应调用成本。不能用稳态延迟替代首次调用来估计 q=1。如果 T_steady 不优于参考方法，不能仅靠增加复用次数宣称摊销后会加速。若新方法准备更贵但稳态调用更快，报告相对于参考方法的盈亏平衡次数；如包含搜索，再单列计入搜索成本的总时间。

### 7.3 主体诊断表

H-Skip 与 V0-R/V2-R 使用相同 R：记录完整的主体调用时间、相对加速、被跳过行/NNZ、校验范围。另列“完整参考/H-Skip”的乐观比，不与完整性能表混合。

### 7.4 参数对照表

默认配置、开发集选出的公共冻结配置、开发网格内逐实例最佳分列，保存所有已测组合，不能只保留赢家。Skip、串行正确性版本和失败数值结果不混入完整并发版本的主性能汇总。

## 8. 结果如何决定下一步

| 观察 | 下一步 |
|---|---|
| 默认完整版本有稳定收益 | 固定当前实现，检查跨矩阵/N表现与预处理摊销，再加入同平台外部基线 |
| 主体 H-Skip 在相同 R 上有收益，完整版本没有 | 优先比较尾部 AIV/补零 Cube，核对负载、启动和准备成本；不直接将差值当作纯尾部成本 |
| 仅“完整基线/H-Skip”有收益，同 R 对照无收益 | 不能认为框架已获益，改善可能主要来自少算输出；继续定位主体 |
| 默认无收益，小网格后公共配置有收益 | 保留两组结果，冻结配置后复测，暂不开发复杂阈值模型 |
| 仅逐实例已测最优有收益 | 说明有参数敏感性，尚不能宣称通用默认配置有效；按目标复用次数评估简单校准是否值得 |
| 结构块数减少但完整执行不快 | 分解 B 准备、数据搬运、实际补齐、并发争用和调用开销 |
| 主体及完整版本在小网格后仍无收益 | 暂缓新分流算法和复杂尾部设计，先检查后端与主要成本；不把该原型失败泛化为原理无效 |

本轮输出是一组可复核的迁移收益与瓶颈证据，不是新颖性证明。除本地方案文件外，当前没有启动设备、没有产生新的性能结果。
