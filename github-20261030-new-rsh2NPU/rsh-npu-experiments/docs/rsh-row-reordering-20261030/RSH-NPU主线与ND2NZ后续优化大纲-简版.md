# RSH-NPU 主线与 ND2NZ 后续优化大纲

## 当前思路

当前研究分成“主线”和“后续优化线”。

主线先追求把 RSH 完整迁移到 NPU，并固定 B 采用 Gather：

```text
RSH 行重排
        ↓
面向 NPU 的细粒度行划分
        ↓
NPU Row Window / 逻辑 Tile
        ↓
类 RS-tile 存储层
        ↓
A/B 数据准备
        ↓
L0A/L0B
        ↓
Cube
```

其中：

- RSH 行重排负责把结构相似的行放到相近位置；
- 细粒度行划分负责同时完成行分流和窗口形成；
- 稠密、结构合适的行进入窗口，稀疏或不适合成块的行分流到向量路径；
- NPU Row Window 和逻辑 Tile 可以先参考 Neutron 的窗口与 `M、N、K` 组织方式；
- 类 RS-tile 存储层需要针对 NPU 重新设计；
- 当前 B 取数先采用 Gather，作为完整系统的基线；
- 先把从 RSH 行重排到 Cube 的完整链路跑通，再讨论 ND2NZ。

## 后续优化线：ND2NZ

ND2NZ 相关的优化暂时不混入主线。RSH 的行重排本来是为了让 RS-tile 构建时，同一个窗口内的列集合更加聚合、窗口更加紧凑。如果在细粒度行划分阶段直接强行追求 B 原始行连续，可能会影响 RSH 原本的窗口结构目标。

后续的 ND2NZ 优化可以单独作为第二条研究线：

```text
固定细粒度行划分
        ↓
只修改 RSH 行重排中的候选行特征
        ↓
生成不同的行顺序
        ↓
形成不同的窗口列集合
        ↓
比较 Gather 与 ND2NZ
```

候选行特征可以作为后续探索变量，例如比较：

```text
方案 A：原 RSH 的非零列一致性或重叠特征
方案 B：非零列连续段特征
```

两种特征分别生成无向图 `G`，再进行后续的行重排。细粒度行划分阶段保持不变，从而观察候选行特征变化带来的影响。

## 两阶段研究路线

### 第一阶段：RSH-NPU 主流程闭环

```text
RSH 行重排
→ NPU 细粒度行划分
→ NPU Row Window
→ 类 RS-tile
→ AIV/AIC 数据准备
→ Gather
→ Cube
```

这一阶段的待办包括：

- 实现 RSH 行重排中的黑盒部分；
- 设计 NPU 版本的细粒度行划分；
- 定义 NPU Row Window 和逻辑 Tile；
- 参考 Neutron 组织窗口和 `M、N、K`；
- 设计适配 NPU 的类 RS-tile 存储层；
- 使用 Gather 打通完整 A/B 供数和 Cube 计算流程。

### 第二阶段：面向 ND2NZ 的结构重排改进

```text
保持窗口划分不变
→ 修改候选行特征
→ 让窗口列集合产生更适合连续搬运的结构
→ 再比较 Gather 与 ND2NZ
```

## 当前阶段的研究表述

当前先验证：

> RSH 的结构重排、NPU 窗口、类 RS-tile 和 Cube 供数能够组成一条完整可运行的主流程。

ND2NZ 作为后续建立在这条主流程之上的优化方向，暂时不作为主流程闭环的必要条件。
