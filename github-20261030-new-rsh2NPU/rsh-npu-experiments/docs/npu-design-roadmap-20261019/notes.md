# 证据与边界

日期：2026-10-19。只读分析及路线文档，没有新设备数据。

## 已有证据

- results/d3/结果解读.md、机制解读.md：J/L 综合时间优势约 1.108×；thermal、web 有明显局部收益，cit 有退化。结果限当前后端、固定已见矩阵、输入驻留调用；强基线和完整准备摊销仍未完成。
- npu/work.h：每 K16 块循环发出 16 次 B 行 DataCopy；A/B 分配双缓冲但没有显式 next-block 预取组织，每次 Mmad 后有 PIPE_M barrier。不能单凭源码证明完全没有重叠，或认定它是主瓶颈。
- npu/work.h 与 npu/restore.cpp：Cube 结果写 packed GM，独立恢复过程经 UB 写回原行号；这是实际存在的额外输出路径。
- 当前预处理输出显式补零的 A 块；这不是完整照搬 RSH 的位图解码内核。
- 相邻窗口默认按轮转分配不同核；是否有足够跨窗 B 复用需要统计，索引重复不等于实际 HBM 流量重复。

## 已核对的公开来源

- RSH §3.3.2：https://arxiv.org/html/2603.08734v1 。GPU 执行设计含操作数构造、寄存器片段映射和流水。研究可沿用划分而改变执行层。
- NeutronSparse §6–7：https://arxiv.org/html/2606.22482v1 。已有局部性、tile 形状、双缓冲、AIV/AIC 协同相关设计，不把通用优化名称认定为新贡献。
- 官方 CANN LoadData：https://www.hiascend.com/document/detail/en/CANNCommunityEdition/910/API/ascendcopapi/docs/en/api/SIMD-API/basic_api/cube_compute_ISASI/cube_compute_load/Load2D.md 。布局/粒度/路径受产品与版本限制；不把典型 GM→L1→L0 路径说成唯一通路，当前环境 CANN9.0.0 须本地校验接口。

## 解释原则

1. 分开画“运行时数据经过哪里”和“研究工作先做什么”。
2. 功能模块有依赖，但性能优化按证据选择；后续模块可以提前成为主要分支。
3. 高效供数是候选主线，不是已测定的瓶颈。先冻结 J 布局，用小范围诊断检验，再选一个机制。
4. 新后端也给适用的 L/F 使用，较强 AIV/外部基线核查与主线并行，避免强行等待全基线完成才允许原型。
5. 常驻 B 仍需每调用读取当前数据；B 更新引起的打包/重排计入正式调用。预先就绪 B 只作条件诊断，不是理论上界。
6. 预处理/新颖性从设计开始记录，在集成阶段做完整验证，不延迟到写论文才查。
