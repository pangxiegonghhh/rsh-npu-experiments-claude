## 新实例准备

1. 先读取续跑说明.md，确认用户此次授权的主版本。每个主版本完成后停止，不自动执行下一版本。
2. 选择实际910B2或记录新SOC差异；准备CANN Ascend C开发工具链、GCC/CMake、Python3.11及NumPy/SciPy。原设备路径/usr/local/Ascend/cann-9.0.0，NumPy2.4.4、SciPy1.17.1、GCC12.3.1。不能仅按目录名认定精确补丁版。
3. 上传项目。紧凑恢复包只含原始CSR、代码、结果、案例元数据和编译程序；若缺少cases_v0二进制，运行 `python3 scripts/restore_v0_cases.py`。它只做CPU恢复，不启动NPU实验，并逐文件校验历史SHA256。
4. 小案例可由 `python3 scripts/make_smoke.py` 恢复；这是CPU布局生成，不运行设备测试。
5. 本机完整性检查：`python3 scripts/audit_v0.py`。审计针对冻结源码与原始输入，不表示计时稳定性已通过。
6. 编译：`cmake -S npu -B build_v4 -DASCEND_CANN_PACKAGE_PATH=/实际/CANN路径 -DSOC_VERSION=实际SOC`，再 `cmake --build build_v4 -j4`。使用新构建目录，保留历史失败日志。不要启动bash登录shell作为环境探针（曾超时）。
7. 已验证的原设备aarch64程序保存在results/v0/device_binary/rsh_runner，SHA256见results/v0/manifest.json。仅兼容环境下复用；重编译/设备变更后重新记录环境与程序哈希，性能比较必须使用当前设备对照。

不要直接重跑已完成的run_v0.py或run_v1.py来恢复文件。它们是设备实验控制器；布局恢复使用restore_v0_cases.py和make_smoke.py。结果目录已有清单时控制器会拒绝不同源码或程序哈希，禁止绕过检查或覆盖旧结果。
