### 可复现的反例（只读本地推导，不是设备故障）

对一次多K计算，设P交换局部K槽0与17，则`(A P)(P^-1 B)=A B`。仅在`split=0`且Kp≥32的路径引入这种共同置换，所有普通乘积和选择器检查仍可通过。只读重算现存160个此类输入，乘积全部保持不变。

具体输入为`artifacts/e0-supplement/20261021-r1/device/inputs/B-selector_K48_N64_l0_b1_element_s0/`：交换后A有2个槽、B有128个槽发生变化，结果与保存的golden最大误差仍为0。原始输入和输出没有改写。这是测试区分能力的反例，不是声称当前loader真的执行了该置换。

已存直装扩展的device debug分别为`[1,16,16,16]`、`[2,16,16,48]`、`[3,16,16,64]`、`[2,16,16,32]`；实际每次Mmad的K均为16。集成也逐K16消费。因此现有直装对照不能独立约束上述一次多K路径。CPU参考独立、零误差、重复更多次，均不能自行消除这一盲区。
