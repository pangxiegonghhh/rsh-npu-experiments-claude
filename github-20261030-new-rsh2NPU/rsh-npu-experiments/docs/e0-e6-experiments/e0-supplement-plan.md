## 4. E0-S1：先让验证器和资源信息可信

### 4.1 平台容量与分配预算

从目标安装包支持的上下文取得真实平台信息，再调用 `PlatformAscendC::GetCoreMemSize` 查询 **L1、L0_A、L0_B、L0_C、UB**，单位为 byte。官方示例使用 `context->GetPlatformInfo()`；本项目独立 runner 如何取得相应平台信息须按安装包确认，不能凭空默认构造或传空指针。[官方 GetCoreMemSize](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_1034.html)

输出每种存储的“平台容量、缓冲份数×单份大小、对齐空隙、已知工作区/预留、合计、剩余”。A1/B1 共同占用 L1，必须合并计数；L0A/B/C 分别计数。预留未知时标为未知，不用 0 代替；编译器/分配器的可用证据一并保存。若未知项影响当前配置的合法性判断，G1不能通过；不得直接用平台总容量声称所有空间可供用户分配。查询容量不等于测得可分配容量上限，不做撑满或超限硬件试验。

固定 W16 时，令 `Np=ceil(N/16)*16`：单份 A 为 `512q B`、B 为 `32qNp B`、C 为 `64Np B`。逐 K16 消费时 L0A/B 可以只容纳一个 K16；一次消费 K=16q 则按 q 放大。所有实际队列缓冲份数按源码记录，不能因为代码称“双缓冲”便假设没有额外工作区。

### 4.2 地址与观测范围

- 记录每条搬运的源/目的位置、元素类型、偏移、长度、stride、repeat、转置和同步顺序。对有限测试输入枚举可访问区间，证明均落在分配的物理空间内。
- 校验 A2/B2 起点满足 512 B、Mmad 的 FP32 CO1 起点满足 256 元素即 1024 B；L1/UB 一般起点按 32 B，具体 API 的更强限制优先。GM 按具体 API 核验，不把 L0 的 512 B 要求泛化到所有 GM 指针。[Mmad 参数要求](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_0249.html)、[一般地址要求](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_0004.html)
- 检查基址和合法的非零分形偏移，尤其多份缓冲的第二份。若 API 可导出真实地址则保存，否则记录分配器保证与偏移证明，明确不是“设备地址读回”。错位、范围越界、非法索引只做 host 拒绝测试，不把非法访问提交设备。

### 4.3 独立微测和参考

计划增加独立 E0 target：单 AIC、先单缓冲，Cube 结果直接写到独立 GM 缓冲回收；不经过现有 restore。记录 launch、stream 同步和输出检查三个阶段；启动失败时数值结果记为“不可解释”，保留原始输出供排查。

CPU 参考从原始逻辑坐标和同一份 FP16 输入做 FP64 乘加。参考及预期坐标不能调用被测打包/反打包函数；原列映射也由 manifest 独立表达。输出布局先用非对称 one-hot 外积检查：覆盖 `(0,0)、(15,15)、(16,16)、(29,39)` 等跨分形位置；再用于后续 A/B 选择器，避免写回和装载错误互相掩盖。

验证器须在本地证明能抓到以下人为破坏：交换两块、漏转置、改一个有效值、改一个规定为零的 padding、改一个 guard、使用越界索引。这些是参考/检查器的自检，不是运行非法设备 kernel。具体用例与失败坐标必须落盘。

## 5. E0-S2：直装路径分层排查

每一层只改变表中的一个因素；每次用独立新进程运行，保留失败日志，控制组与试验组共享输入和数值参考。先串行、明确同步，性能留给 E5。

| 顺序 | 试验 | 如何解释 |
|---|---|---|
| D0 | 最小常规装载 `GM→L1→L0A`，16/16/16 | 失败则先处理环境/入口/共同部分，不能归因直装 |
| D1 | 以单入口、独立编译目标承载同一个常规 kernel | 验证独立 target 的打包、注册与启动链 |
| D2 | 保持 D1 的 B、Mmad 和写回不变，只将 A 换为 GM→L0A | 隔离 A 直装；核对 GM 中单个 16×16 预排布分形与全部 LoadData 参数 |
| D3 | 若 D2 正确，把两种已正确的入口放回双入口产物，仍独立进程调用 | 只有此时失败才支持打包/注册相关假设；保存符号及运行差异 |
| D4 | 逐步接回现有队列、循环、dispatch 和 restore，每步对照上一版本 | 定位集成/同步；不一次恢复全部复杂度 |

若 D2 仍失败，按“目标安装包接口签名/支持型号→源字节布局和地址范围→装载参数→对应搬运与计算同步”的顺序检查；核对安装包日志/错误码定义，不靠数字猜根因。同一条件不盲目循环重试，每次重试须有记录的假设和单项改动。若发生设备异常，先回收日志并结束当前异常进程，环境恢复后才能继续，异常结果不参与数值判定。

在线 Load2D 文档列出 GM→A2 路径，分形内转置限定在 A1→A2/B1→B2；补测仍须以目标安装包为准。A 直装使用预排布 A，不在这一步引入 B 直装或压缩解码。[官方 Load2D](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_00169.html)

最小例通过后，直装路径增加 `M16/U32/N33`、`M16/U48/N64`、`M16/U17/N17`：覆盖多个 A 分形、N 多块和 K 尾补齐；同步执行同输入常规控制，采用 S4 的边界检查。若只通过最小独立例，集成仍失败，不能宣称现有直装原型已可用。

直装最终状态只能为：

- **PASS**：最小例、扩展例及集成所需路径数值/边界通过，记录适用范围。
- **CONFIRMED_UNSUPPORTED**：有目标 910B2 / 安装版本的明确接口限制与最小案例佐证；写入证据后关闭该候选路径，E5 不测试它。当前在线文档列出该路径，若产生相反判断必须解释版本/接口差异；单次编译或启动错误不能作为该结论。
- **FAIL / UNRESOLVED**：仍有未归因失败、只有编译成功或独立例通过。E0 保持待补测；时间花完不是通过理由。

## 6. E0-S3：独立证明 A/B 的布局和搬运

### 6.1 地址协议与输入标签

沿用[输入契约 §2](../window-format-research-20261021/cube-input-contract.md)的轴序，落盘时写元素偏移和 byte 偏移，不能只写 ZZ/NZ/ZN 名称。设 `Mb=ceil(M/16)`、`Kb=ceil(K/16)`、`Nb=ceil(N/16)`：

```text
A1 整块 NZ: (((k1*Mb+m1)*16+m0)*16+k0)
A2 ZZ:     (((m1*Kb+k1)*16+m0)*16+k0)
B1 整块 NZ: (((n1*Kb+k1)*16+k0)*16+n0)
B 暂存:     (((k1*Nb+n1)*16+k0)*16+n0)
B2 ZN:     (((k1*Nb+n1)*16+n0)*16+k0)
C NZ:      (((n1*Mb+m1)*16+m0)*16+n0)
```

A/B byte 偏移为上式×2，FP32 C 为上式×4。W16 的 `Mb=1`，A1/A2 两式相同；不能用这个特例证明 M>16 也无需重新安排。

用两轮可精确表示的 FP16 非零标签分别编码“分形编号+1”和“分形内坐标+1”（块内为1～256），合起来唯一识别每个槽，避免首槽标签为0而漏搬未被发现；不要把过大的连续整数强行写成 FP16 后假称唯一。乘积验证另用首轮小整数/二进制分数输入，保持精确参考。

### 6.2 最小覆盖矩阵与独立选择器

| 子项 | 最小输入／变化 | 观测及通过条件 |
|---|---|---|
| A-LAYOUT | W16，U=16/32/48；逐 K16 装载与一次多分形装载 | B 为独立生成的单位基，分批选出每个 A 列；输出逐坐标等于原逻辑 A |
| B-LAYOUT | W16，U=16/32/48 与 Np=16/32/64 全组合；两种 B 暂存轴序 | A 为独立单位基，分批选出每个 B 行；多 K、多 N 同时出现的组合必须通过，不能只跑单分形 |
| B-MAP | U=32，N=33；连续映射、`3j+1` 散列映射、两段连续的稀疏映射 | 每种映射单独冻结；期望为 `B_global[col_idx[j],n]`，不把局部 j 当原行号 |
| WRITEBACK | 非对称输出、多 M/N 分形的 one-hot 外积 | 验证 Fixpipe 的 stride/写回坐标；先查 packed，再查集成 restore |

两种 B 方案最终必须得到同一 B2 元素顺序。分别从各自的 B1 地址表推导 `startIndex/srcStride/dstGap/repeatTimes/ifTranspose`；逐 K16 暂存不能借用整块 NZ 的偏移公式。`q>1、Nb>1` 用来暴露分形间顺序错误；一次多分形装载与多次单分形装载单独记结果。

单位基操作数用独立、可手工核对的物理槽表构造，不与被测一侧共享布局函数；其装载路径先以目标官方最小示例和单分形one-hot输出核验，然后冻结搬运参数。每次只替换被测一侧，禁止同时使用两侧候选loader；比较两种B布局时，A选择器及其参考装载路径完全固定，避免相同K置换在两侧抵消。对所有有效列/行分批选择，不能只挑几个角点就称全布局通过。

### 6.3 证据等级

GM 输入/host 预排布可逐 byte 验证；L1 只有确认目标版本存在合法读回路径后才增加读回。L0A/B 没有已确认的直接读回接口时，用上述选择器验证**设备可观测元素映射**，配合地址枚举；明确记录 `selector_observed`，不能写成 `raw_L0_dump`。一般矩阵的最终乘积一致仅为回归证据，不能替代这组独立选择器。

## 7. E0-S4：尾部、相邻窗口和边界

### 7.1 先明确四个区域

1. **逻辑有效区**：与独立 CPU 参考逐元素比较。
2. **项目规定的零填充区**：当前 W16/K16 路径实际计算到物理 Np；A 无效行/K槽、B 无效 K行/N列必须按协议补零，packed 对应 M/N 填充区应为零。
3. **API 未承诺值的物理输出位置**：例如单次非整倍数逻辑 Mmad 的无效输出区域，单独记录，不强制为零，不与第2类混为一谈。
4. **分配外侧保护区（guard）**：在同一个合法大分配内围住被测子区，前后至少各 1024 B，并保持 API 所需对齐；运行前后逐 byte 一致。源/索引区另记录哈希，检查是否被意外写入。

guard 变化可以证明写坏；guard 未变**不能证明没有越界读**。读边界须同时审计每条实际搬运的范围，并在合法分配内更换有限数值哨兵，检查无关区变化是否影响有效输出。只对已声明不参与计算的区做扰动；不能把协议要求为零的 K 填充直接改成非零，再误判原路径错误。工具链若有已核验适用的越界检测工具，可追加证据，不预设可用。

### 7.2 必测用例

| 用例 | 路径/输入 | 必须暴露的问题 |
|---|---|---|
| N-TAIL | 原来的 U=16/32/48，N=17/33 六组，W16 | 重新加观测后读回完整 packed 和最终输出，检查有效列、规定零列、guard |
| K-TAIL | W16：U=1/5/15，N17；U17，N17/33；U31，N33；U37，N33 | 满块+尾块，`valid_k` 边界、最后一个映射、零行哨兵 |
| COMPACT-LOAD | 单块 `A[16,valid_k]`，valid_k=1/5/15，与显式补零 `A[16,16]` 对照 | 只测 DenseTail 所依赖的 ND2NZ 装载原语，GM 行跨度/逻辑宽度/目标补零；不做 E1 的完整编码比较 |
| ADJACENT | 同一调用两个固定窗口 U17 与 U37，N33，值和原列映射明显不同 | 尾块读到下一个窗口、块指针错误、窗口输出串写；窗口成员不变 |
| M-TAIL | 首轮 M30/U70/N40 分解案例，两个 W16 | 第二区域的无效两行、row_map=-1、restore 的写回范围 |

ND2NZ 对 D 方向不足 32 B 的部分有补零说明；紧凑装载仍需核验具体 stride、物理分配和所有目标槽。[官方 ND2NZ](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_00127.html)

补零观察也要逐侧独立：A尾槽通过固定B单位基选择出来，B尾行/尾列通过固定A单位基选择出来，诊断调用覆盖补齐后的物理尺寸。不能仅因A尾列和B尾行的乘积为零，就认定两边都正确补零；其中一侧全零会掩盖另一侧错误。

稠密补齐基线允许把无效 colref 指向已分配的全零 B 哨兵行；记录 `global_K` 和额外哨兵行，不能让其落在 B 分配外。紧凑映射如果只存 valid_k 个索引，必须在读取前判断 valid_k；本轮不要求实现新紧凑映射 kernel，也不能声称已验证它。

输出 payload 运行前用非零标记初始化以检测漏写；明确由 host 或 kernel 负责清零的区域另记。每例回收完整 packed、最终输出及 guard。恢复行序使用冻结/合成输入中既定 row_map，不重新排序；无效行不会被恢复到合法输出行。

## 8. E0-S5：一次逻辑 Mmad 与分步累加分开测

### 8.1 W16 多 K16

用 `M16/K32/N32`、`M16/K48/N64` 对比：

- q 次 `Mmad(m=16,k=16,n=Np)`，同一 CO1 首次初始化、后续累加。
- 一次 `Mmad(m=16,k=16q,n=Np)`，A/B 预先按完整 L0 布局装载。

两者用相同逻辑 A/B、独立 CPU 参考；加入有正负抵消的小二进制分数，验证累加初始化和跨 K 块数据。先过 S3 布局、S1 资源，才比较计算。这里只有正确性对照，不把调用数减少推断成提速。

### 8.2 真正的 M30/K70/N40

该用例是 API 契约诊断，不改变项目 W16 窗口策略。独立微测在设备端**确实执行一次** `Mmad(m=30,k=70,n=40)`；保存参数、源码/产物对应及实际调用计数证据，不能通过改 case 名代替。

计划物理形状为 A：32×80，B：80×48，C：32×48；FP16 A/B 分别 5120/7680 B，FP32 C 为 6144 B，不含对齐/工作区。此时 A 的 m1 有两个取值，NZ→ZZ 分形间安排不再可用 W16 等价式省略。

零填充基线为必测，有效30×40结果须与逻辑K70参考一致。另列M无效行、N无效列、K无效归约槽三类区域，逐类记录“是否允许扰动、依据、预期行为”：只有目标API明确保证忽略的区域，才做有限非零哨兵扰动并要求有效结果不变；若要求调用方补零，就保持零并验证补零，不把非零输入作为必过条件。契约不明确的区域保留待核验；这不允许省略单次30/70/40零填充基线。CO1无效输出不假设其数值，写回使用目标安装包确认的合法参数，核对允许写入范围及外侧guard。在线文档给出该非整倍数示例；目标版本的具体边界按安装包与实测共同记录。[Mmad 非整倍数示例](https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_0249.html)

输出 `logical_m/k/n`、`physical_m/k/n`、`mmad_call_count`、逐次调用参数、有效区最大误差，以及无效区策略。首轮两窗口替代案例只作单列对照，不能计入本项通过数。

## 9. 统一数值、运行和数据协议

这是确定性输入契约验证，无需功效分析、p 值或性能排名。单位基标签、小整数/二进制分数应精确匹配（最大绝对误差0）；任何有效输出非有限均失败。另加一般 FP16 输入时沿用研究报告误差协议，不放宽现有 `0.01+0.01*abs(reference)` 上限，并报告最大绝对误差及归一化误差。

修复前后保留单独 run ID。各最小诊断例先单次启动定位；最终通过的核心配置在3个新进程中复核，每个进程交替不同 A/B 输入重复10次，逐次验证，排查状态残留。核心配置至少包含S0三组控制、直装最小例（若适用）、S3的U48/N64两种B布局、S4相邻窗口及S5单次30/70/40；其余必测组合至少完整运行一次。这是正确性复核，不是E3～E6的性能采样协议。host时间只作运行记录，不称设备kernel时间。

每次运行记录 PID/开始时间/结束状态；小型设备微测单进程暂定120秒硬超时，构建暂定10分钟，均是防挂起的执行上限，不是性能阈值。每30秒检查原进程和日志；工具等待返回不等于进程结束，不新开重复任务。超时保存日志后结束该进程，标记 TIMEOUT；有明确证据需要延长时先修订并记录上限。任何收尾都不启动 E1。

建议当轮目录：`artifacts/e0-supplement/<run_id>/`，执行时才创建；至少包含：

| 文件 | 必需内容 |
|---|---|
| `manifest.json`、`commands.txt` | 方案版本、环境、源码/输入/二进制 SHA-256、完整命令、seed、run ID、父版本 |
| `environment.txt`、`resources.json` | SoC/软件版本、五种容量、各区域预算及证据 |
| `configure.log`、`build.log`、`run-*.log` | 完整 stdout/stderr、返回码、各层失败上下文 |
| `cases.json`、`address-map.json` | 逻辑/物理尺寸、原列号、布局、全部搬运参数及合法地址范围 |
| `outputs/`、`checks.json` | 原始 FP32 输出/guard；有效/padding/guard 数量和错误坐标，观察方式 |
| `summary.md`、`checksums.sha256`、`instance-off.png` | 各子项判定、未完成项、下一步、本地与远端校验、实例停止证据 |

`checks.json` 每项至少记录 `step_id/case_id/path/status/launch_status/sync_status/logical_shape/physical_shape/max_abs_error/padding_errors/guard_errors/read_range_check/observation_method/evidence_files`。未测或不可观测字段为 null 并带原因，不能填0或 true。FAIL、TIMEOUT、NOT_RUN 也必须进入汇总，不能只导出通过项。每完成一个子步骤即回收小结果，结束时回收完整日志与输出，避免再次丢失构建日志。
