### 结果与判定

E0 首轮设备结果：常规 V1 Cube 路径的 15 组 W16/K16×N 组合和 1 组 M30/压缩K70/N40 替代案例，**16/16 有效输出通过，最大绝对误差 0**。这些值是端到端带同步的主机调用结果，不是纯 kernel 延迟。直接 GM→L0A 试验在首例失败；资源、padding guard、独立字节布局和真正的非整倍数逻辑 Mmad 尚未测完。因此 E0 仍为待补测，**E1 不得启动**。本地先前的 CPU 格式研究通过1988项语义检查与20项布局检查，见[研究阶段结果](../window-format-research-20261021/probe-results.json)；那不是E0设备结论。

结束门槛：目标环境编译可复现；所有必选尺寸的设备输出逐元素与CPU参考比对并报告最大误差；写回尾部、padding及guard未越界；资源/地址要求记录。若任一项不满足，E0标记失败或待续，不进入E1。结束前备份本地可用日志与结果并核验，关闭实例。

上述门槛由[补测计划§10](e0-supplement-plan.md)具体化为G0～G6：padding区和guard分开判定，guard不变不能证明无越界读；直装须取得正确性通过或有明确目标依据的不适用结论。未定位启动错误仍保留待补测，当前没有任何新增门槛已通过。
