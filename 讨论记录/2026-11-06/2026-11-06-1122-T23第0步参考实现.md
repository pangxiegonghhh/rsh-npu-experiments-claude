## 2. 规格空白的补全（规划方自定，属 T23 实现细节；全文见参考实现 README §2–§5）

| 处 | 规格原文 | 补全 |
|---|---|---|
| P 的扫描 | 「从剩余最小组开始扫描」 | 其余短组按（大小升序、最小原行号升序）依次检查，能整组并入就并，目标满 W 即停；被并入的组不再当目标 |
| P 的输出 | 「组内按原行号升序」 | 原完整组、新完整组、剩余短组三段都按此；C2 的「生成顺序」= 满员先后，C3 = 创建先后 |
| C3-W4-noP | 「按生成顺序展平原组」 | 按创建顺序，组内仍按原行号升序 |
| C2 的 MinHash | 「具体 hash 算法随实现记录」 | (a·(x+1)+b) mod (2⁶¹−1)，a、b 由 SHA-256 派生，不依赖库随机数 |
| C2 的下限 | 「起始建议 0.2」 | J ≥ 0.2（含等号），与 C3 的代码口径一致 |
| 分数比较 | 「可交叉相乘比较」 | 全部精确比较（分数或整数交叉相乘），不用浮点 |

这些补全不改变各候选的研究含义，只把执行方会各自猜测的地方定死，以保证跨实现逐位一致。
