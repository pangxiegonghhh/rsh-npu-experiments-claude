# 修订后的流程与代办

## 与原大纲的关系

原大纲（`RSH-NPU主线与ND2NZ后续优化大纲-简版.md`）的分层结构保留。修订点：

- 增加贯穿各层的统一代价模型，作为每层的评价目标。
- 列置换从观察项升为正式变量（用户已同意）。
- ND2NZ 从"另一条研究线"降为第 5 层的执行选项，是否使用由代价模型和段长分布决定。
- 存储层拆为结构 + 载荷，载荷增加 Dense-NZ 选项。
- "细粒度行划分同时得到窗口集合和残余集合"原大纲已写明，不需改（用户纠正）。

## 流程图（★ 为代办）

```text
┌──────────────── 统一代价模型（各层共同的评价目标）────────────────┐
│  AIC：T（K 方向块数）、R（B 段数）、A 载荷字节、B 字节              │
│  AIV：残余 nnz × N                                                  │
│  ★ 系数待 G2 / E3-ext 实测标定，先用代理指标                         │
└─────────────────────────────────────────────────────────────────────┘
                              │
第 1 层  全局重排（行 / 行+列对称置换）
         ★ 评价器扩展：加入 R、对称置换视图、多个 W、"划分后"评价
         ★ 补全 B-Neutron-ref 的行/列抽取（Len ≤ α·K）
         ★ 首轮候选比较方案（精简与否待讨论，见 07）
                              ↓
第 2 层  细粒度行划分（一次扫描，同时得到窗口 W 和残余集合 C）
         ★ 流水线 B 的算法设计：融合调研中的成窗类候选
           与 Δ 判据（判据方向按 NPU 代价重新确定）
         ★ G1：流水线 B vs NeutronSparse（相同 AIC nnz 占比）
                              ↓
第 3 层  Row Window / 逻辑 Tile（W ∈ 16…128；可变高度后置）
                              ↓
第 4 层  类 RS-tile 存储：结构（窗口偏移 + 压缩列号）
         载荷：Bitmap / Index / Dense-NZ
         ★ E3-ext：Dense-NZ 离线预排直装 vs AIV 解码 Bitmap
           在有残余并发的条件下比较，并检查 A 的存储容量
                              ↓
第 5 层  A/B 数据准备：A 直装或解码；B 逐行 Gather / 按段 ND2NZ
         ★ G2：段长 L 对应 GM→L1 耗时曲线（AIC 侧，含双缓冲）
                              ↓
第 6 层  L0A/L0B → Cube（AIC） ∥ AIV 残余路径
```

## 判断树

```text
G1：相同 AIC nnz 占比下，流水线 B 的 padding / T 是否明显少于 NeutronSparse？
 ├─ 否 → 上下文感知划分的空间有限，重新找切入点（G2 不用看）
 └─ 是 → G2：B 的段数对供数耗时影响大吗（已计入双缓冲重叠）？
          ├─ 是 → 主线：B 供数代价驱动的划分 + 布局协同设计
          └─ 否 → 主线：上下文感知划分；ND2NZ 只作工程优化
```
