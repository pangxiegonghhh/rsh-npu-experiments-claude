# 初始评审七条意见（2026-11-02）

总体判断：路线改为自顶向下是对的。先定结构层、主线先用 Gather、ND2NZ 后置，这个方向成立。停在 E4 的理由也成立：ND2NZ 的收益取决于窗口引用的 B 行能否连成长段，上层结构不定，E4 的数字没有推广价值。

## 七条需要调整的地方

1. **只改行顺序，列号不会变连续。** 行置换不改变列号，ND2NZ 的上限被锁死。合成结果：RSH 把窗口平均非零列从 79.8 降到 46，但平均段长从 2.70 降到 1.56。建议加入列置换，GNN 方阵可用对称置换 PAPᵀ，B 只需进入时置换一次。NeutronSparse 的 Global 阶段本来就同时重排行列（§6.1）。
2. **第一层就记录 ND2NZ 将来要用的指标。** 增加 DMA 次数代理：按"每段一次搬运"和"每行一次搬运"分别计数，再按 N 换算字节。
3. **评多种窗口高度。** 同时输出 W=16、32、64、128。另：NeutronSparse 写 L0C 256 KB，E0 实测 910B2 为 131072 B（128 KB），双缓冲下 M=128 时 N 最大 128，照搬 (128,256,64) 会超容量。
4. **"每层固定后再进下一层"太严格。** 层间依赖是双向的。建议先用最简单选择拉通粗糙端到端链路，再逐层替换。
5. **划分与成窗的先后要写明。** RSH 重排后顺序扫描，用 Δ 判据同时决定进窗口还是进残余；NeutronSparse 先抽取后重排。建议加"剔除短行后再评价"的变体。
6. **存储层不要默认 Bitmap。** Cube 不能直接读 Bitmap，AIV 解码要走 UB→GM→L1。建议把预排 Dense-NZ 作为对照基线。（后续讨论见 05）
7. **和 NeutronSparse 的差异要提前想清楚。**（后续讨论见 02、03）

## 第一层程序的具体问题

- RSH 论文用 w-Jaccard，w_j = d_j^(−α)，α>0；程序默认 `weighted-alpha=0`（普通 Jaccard），正式实验应改为 α>0 或两组都跑。
- 论文写最小生成树，程序在相似度上做最大生成树，两者等价（1−sim 上的最小生成树），文档应注明。
- 倒排索引候选成本约 Σ deg(col)²，human_gene1（AvgL≈1107、NNZ≈2467 万）纯 Python 可能跑不完。可换小矩阵、截断高频列或用 MinHash，需记录。
- 数据集偏长行稠密矩阵，建议加入 ogbn-arxiv 或 RSH Table 1 中的图（amazon0505、DD 等），否则体现不出 RSH 的短行隔离优势。
