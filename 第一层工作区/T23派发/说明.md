## 4. 评价网格

每个候选、每张矩阵、每个 W，按 `conditions_ref.py` 的定义出这些行（A0、A1 各一套）：

| τ | 放置 | D 规则 | 说明 |
|---|---|---|---|
| 全行（none） | none | own、D-greedy | own = 候选行序本身；D-greedy = `rq2lib.dstage(π, adj, intra='greedy')` |
| 每个 τ | **tail-co** | own、**D-greedy** | **主口径为 tail-co + D-greedy**；own + tail-co = π_K + co_chain(D)（AIC 窗口内不做 D 阶段，残余区按 co 链） |
| 每个 τ | tail | own、D-greedy | 参照：own + tail = π_K + D（按 π 中的相对顺序） |

- **τ 规则与 T22 相同**：cora、ogbn-arxiv、wiki-RfA 用 τ ∈ {2, 3}；dawson5、olafu、pattern1、human_gene1 用分位数 τ_q20、τ_q40（方案 §4、T22 派发说明 §3）。
  若 T22 已交回，直接取其实算的 τ 值并核对一致。残余集合一律按 A0 度数定，A1 用同一集合；A1 下 D-greedy 与 co 用 A1 的邻接。
- **后处理之后（source = post-E）**：对每个 P0 候选在每个 τ 下做 P-LS(0)（A0，最多 10 轮，种子 0，规则同 T21 J1），再按上表 tail-co 的 own 与 D-greedy 两行评价（A0、A1），
  另报 sweeps_done、accepted_swaps、后处理耗时。
- **D 阶段守门**（方案 §4）由规划方在判读时用 own 与 D-greedy 两行完成，**执行方照常输出两行，不新增行**。
- **co_chain 的守卫**：`rq3lib.co_chain` 中某个窗口用到的残余点超过 400 个时，该窗口不参与 co 计数（Cora 上从不触发）。**移植时原样保留**，并在 README 记录每张矩阵、每个 τ 的触发窗口数。
- T_ratio_B0 = 同一「矩阵 × 口径 × W × τ × 放置 × D 规则」下 T / T(B0)。category 按方案 §2 的类别填写。
- **评价器自检**：执行方的评价器在 Cora 上对 B0 与 C4-U 跑出的 40 行，须与 `expected_conditions_cora.json` 逐字段相等（运行 `python3 -B conditions_ref.py --cora-selfcheck` 可复现）。
