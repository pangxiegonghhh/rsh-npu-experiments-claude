## 2. 代码改动（只改 `rect.cpp` 的 `rsh()`，另编新库）

**不要修改 `librect.dylib` 与 `rect.cpp` 原文件。**

**参考实现已写好：本目录 `rect_t4.cpp`**（审核者按下述规格实现，相对 `rect.cpp` 只新增 57 行、原有行零改动，已在审核环境的 cora 上验证，方案 §5.5）。做法：

1. 先 `diff` 本目录的 `rect_t4.cpp` 与你 T23 工作目录里的 `rect.cpp`，**确认只有新增行**（若你的 `rect.cpp` 与仓库副本不同，停下报告）。
2. 用与 `librect.dylib` 相同的编译器与选项把它编译成 `librect-t4.dylib`（审核环境用的是 `g++ -O2 -std=c++17 -shared -fPIC`；macOS 上用 clang++ 亦可，加 `-std=c++17`）；**不要**加 `-ffast-math` 之类改变浮点运算顺序的选项。编译选项记录在 manifest。

下面是 `rect_t4.cpp` 实现的规格，供核对；你也可以自行实现，但必须同样通过上面的自检。

新增导出函数（原 `rect_order` 与原 `rsh()` 保持不变；`rect_t4.cpp` 中以新成员函数 `rsh_t4()` 实现）：

```c
void rect_order_rsh(void* p, double alpha, int k, int iso_mode, int32_t* out);
//   iso_mode: 0 = 尾部（B1 的做法）；1 = 原文的局部孤立行就近放置（方案 §6.4）
long rect_last_local_isolated(void* p);  // 上一次调用的局部孤立行数（iso_mode=1 时）
long rect_last_moved(void* p);           // 上一次调用实际移动的行数
```

`rsh_t4()` 相对原 `rsh()` 的四处改动（方案 §3.4）：

1. **列权重**：预先算 `w[j] = pow((double)inv[j].size(), -alpha)`，`inv[j].size()==0` 时 `w[j]=0`；再算 `wdeg[v] = Σ_{j∈s[v]} w[j]`。
2. **候选打分**：原来 `if(counts[u]++==0)touched.push_back(u);` 与 `-double(counts[u])/(deg[v]+deg[u]-counts[u])`。α > 0 时改为加权累加 `wcnt[u] += w[c]`，分数 `-wcnt[u]/(wdeg[v]+wdeg[u]-wcnt[u])`；`partial_sort` 的截断数 `min(8, …)` 改为 `min(k, …)`。**破平局规则不变**（`(−sim, 行号)`）。
3. **2-opt 代价**：所调用的 `sim(u,v)` 在 α > 0 时改为加权版：归并循环中相等分支累加 `w[该列]`，分母 `wdeg[u]+wdeg[v]-z`，分母为 0 时返回 1.0（与原版约定相同）。
4. **α = 0 时一律走原来的整数路径**，不经浮点权重，保证 `(α, k, iso) = (0, 8, 0)` 与 B1 逐位相同。

每个共享列只做一次 O(1) 加法，复杂度与原版相同；**不得**实现成逐对重新遍历交集。

**iso_mode = 1 的定义**（方案 §6.4，审核者的落成口径，原文未给判定标准）：

- 时点：2-opt 结束之后。
- 判定：以 2-opt 后的行序 π 为准，第 i 位的行 r 若与 π[i−1]、π[i+1] 都不共用任何列（首尾只看一侧），**且**全局至少与一行共用列，则为局部孤立。全局零共列的行（kNN 边集为空，即 B1 的孤立行）不动，仍在尾部。
- 移动：按位置从前到后逐个处理；对每个局部孤立行 r，在其候选集中取 w-Jaccard 相似度最高的行 u（平局取行号小者），把 r 移到 u 之后。**只做一遍。**
- 报出：局部孤立行数、实际移动数。

Python 侧：在 `native.py` 的 `Rect` 里加一个方法 `order_rsh(alpha, k, iso_mode)` 调用新库，返回值同样映射回原编号（`[self.K[i] for i in out]`），空行按原编号升序接在最后（与 `new_full_order.py` 的约定一致）。行序写成与 T23 相同格式的 `*.order.json` 与 `*.record.json`，`record` 里 `t23_member = "B-RSH-ref"`、`params = "alpha=…,k=…,iso=tail|near"`。

## 3. 自检（报数前必须通过，否则本轮作废）

0. **cora 落成自检**：§2 第 3 步的 `check_rect_t4_cora.py` 打印 PASS。
1. **复现 B1（最重要）**：`(α, k, iso) = (0, 8, tail)` 在 cora、ogbn-arxiv、reddit、ogbn-products 四张上的**行置换**与 T23 中 B1 的逐位相同。参考文件与哈希见方案 §7.1 的表。**比置换，不比文件字节**（T21 的文件带元数据；读入后取 `row_perm` 或整个列表）。
   - cora、ogbn-arxiv 的参考来自 T21 的 accelerate-v8，与 `rect.cpp` 只可能在**空行**的尾部位置不同（方案 §3.1）。若不同：检查差异是否**只**在度为 0 的行上——是，则记录差异行数，并改为核对 T23 中 B1 在主口径与全行下的 ΣU、T 逐值相等；否，则停。cora 无空行，必须逐位相同。
   - reddit、ogbn-products 的参考本就出自 `rect.cpp`，**必须逐位相同，没有例外**。
   - 若只走「否」分支（§4），reddit、ogbn-products 也要跑这一次 `(0, 8, tail)` 核对——它同时是 §5 的计时校准点之一。
2. **确定性**：调参选出的组合在 cora 上连跑两次，置换相同。
3. **参数生效**：α > 0 时置换须与 α = 0 不同；k ≠ 8 时置换须与 k = 8 不同**或**在 manifest 里说明为何相同（cora 上 k = 16 与 k = 32 本就相同，审核环境已验）。iso = near 时若局部孤立行数 > 0，置换须与 iso = tail 不同。
4. **评价器**：沿用 T23 的 `evaluate_t23.py`，不改；`logs/layout-port-gate.json` 必须仍为 passed。

## 5. 计时与主机

- 每次行序生成记录 `order_sec`、峰值内存、`recorded_execution_host_id`。
- 校准点：C4-U（T23 同主机八张合计 12 秒）、(0, 8, tail) 的 B-RSH-ref（即 B1，T23 八张合计 449 秒；「否」分支只有 cora、ogbn-arxiv、reddit 三张同主机实测，按这三张比）。报「本轮 / T23 记录」的比值。比值落在 0.8–1.25 以外不影响你的执行，照常报出，由规划方按方案 §4.2 处理。

## 6. 诊断量（每次行序生成都报）

孤立行数（kNN 边集为空）、kNN 图连通分量数、iso = near 时的局部孤立行数与移动数、候选对总数。

## 7. 时限

单个「矩阵 × 参数组合」的行序生成 3600 秒（nnz > 1e7）或 600 秒（nnz ≤ 1e7）；评价沿用 T23 的时限与 8 GiB 工作空间预算。超时记 INCOMPLETE 并报已完成部分，不改参数、不重试。ogbn-products 的 tail-co + D-greedy 在 T23 已因工作空间预算大面积 INCOMPLETE，本轮照旧，不影响 T。
