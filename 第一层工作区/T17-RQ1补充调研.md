## 0. 结论摘要

1. **新条件改变了几类候选的前提，没有推翻任何候选。** C1、C2、C7 入选理由在新条件下照常成立；
   C3、C4 的一个隐含前提（原始列号有局部性）在 Cora 上不成立，建议加"先粗排再用"的阶段互换变体；
   C5 在对称场景下应加单部图 Rabbit 变体；C6 在 GNN 可摊薄条件下建议由补充升为主候选。（§2）
2. **建议新增两类候选：** METIS 边割划分（C8，Merkel 等 PVLDB 2025 中 GNN 训练加速最好的一类）与
   Gorder（C9，窗口内"共同邻居"打分，形式上最接近 U_w，且自带一项与 R 有关的"互为邻居"项）。
   Acc-SpMM 的局部链接规则作为 C5 的局部阶段变体，不单列。（§3）
3. **转交后两块调研：** BP 递归二分、RCM 转交空白一（主要作用于 R）；度数类排序转交空白二
   （与 nz_r ≤ τ 划分天然对齐）。（§3.3）
4. **一条高优先级发现（第四象限）：** 2026-11-01 上线的 **Ascend-SpMM**（arXiv 2611.01936）是新的
   昇腾 SpMM 工作，摘要称有"按密度把稠密区域分给 Cube、稀疏余量分给 Vector"的任务映射和以访存为中心的
   代价模型，可能与 motivation 和创新点 1 相邻。本会话正文抓取被限流，**未读正文**。（§4）

## 1. 新条件与 Cora 上的两组数

骨架指定的新条件：

| 记号 | 新条件 | 出处 |
|---|---|---|
| N1 | 划分后评价（nz_r ≤ τ 送残余，剩余行重新切窗） | 骨架 §3.3、T12 |
| N2 | GNN 场景：A 对称、固定、反复调用，预处理可摊薄 | P1 |
| N3 | W 可变（16/32/64/128） | 骨架 §3.2 |
| N4 | 对称置换为主视图 | P2 |

N4 只影响 R，不影响 U（`08` 正交性【沿用】），故对 RQ1 的影响仅在 C5 一处（§2）。

**两组本稿自算的数**（输入：`第一层实验结果/cora-pilot-20261104/` 的 `cora.mtx` 与 `window_metrics.csv`）：

- **原始列号几乎没有连号。** original 视图 ΣR/ΣU = 50.38/56.37 = **0.894**，即窗口用到的列有约 89%
  各自单独成段。rabbit、neutron 的 row_only 视图同为 0.88，native 视图降到 0.49–0.51。
  含义：Cora 的原始编号对"列号相近"不携带结构信息。
- **短行占比高。** Cora（对称展开后 10556 nnz）度数中位数 3、均值 3.90、最大 168。
  按 nz_r ≤ τ 送残余：

  | τ | 送残余的行 | 占行数 | 占 nnz |
  |---|---|---|---|
  | 2 | 1068 | 39.4% | 15.6% |
  | 3 | 1621 | 59.9% | 31.4% |
  | 4 | 2010 | 74.2% | 46.1% |

  τ 尚未定，此表只说明：**在 GNN 图上，划分后 AIC 侧可能只剩少数较长的行**。这放大了 N1 的
  影响，也放大了 P10（残余点的编号位置）对 R 的影响。

## 2. C1–C7 在新条件下的复核

| 候选 | 原入选理由（`candidates.md`） | 新条件下的判断 | 建议 |
|---|---|---|---|
| C1 Groot 树序 | 先生成行序，与层次兼容；Hamming/Jaccard 对比 | **N3 下更有利**：只输出行序，一次计算可在任意 W 切窗。**N1**：树 DFS 序中相邻行相似、远处渐变，删行后窗口前移几行，受成员平移的损失推测较小【待核】 | 保留，不改 |
| C2 LSH 限容量合并 | 直接保留相似行组 | **N1**：组恰为 W 行，删行后组被切开，成员平移损失推测较大【待核】。**N2**：幂律图的 hub 让 LSH 大桶更多（原文已列为失败条件）；但划分后剩下的是长行，MinHash 对长行估计更准。**N3**：容量 W 写死，每个 W 重跑 | 保留；成本按每个 W 分别记 |
| C3-W1/W4/A BlockSmith | 粗签名降成本、在线聚类 | **前提不成立**：b=4 把相邻原始列号并成一个特征，依赖原始编号有局部性，Cora 上 ΣR/ΣU=0.894 说明没有。C3-A 在 GNN 大图上取 b=128（ogbn-arxiv 169,343 行【沿用 Table 2】；reddit、amazon-product 按 D≥100K 也取 128【规模待核】），粗化更严重 | 保留 C3-W1；C3-W4/A 加**"先粗排再分桶"变体**：在 Rabbit 序（或 C8 序）的新编号上取签名。这正是骨架 §4.2 第 2 条的"跨方法阶段互换"，不必新立候选 |
| C4-U/T LOA | 直接考察整组密度 | **同样的前提问题**：候选池取"按最小非零列号排序"的前 L=128 行，原始编号无局部性时，池子近于随机。HC-SpMM 原文面向图（P07），其数据集编号是否有局部性【待核】 | 保留；加**候选池换成粗排序列**的阶段互换变体（与 C5 的"粗序限范围"同构，可直接比较） |
| C5 Rabbit+anchor | 社区粗序限制局部搜索 | **N4**：现规格在二部图上跑 Rabbit，行顶点与列顶点各得一个编号，属于独立视图（与 P5 同源）。GNN 的 A 对称，**单部图 Rabbit** 只给每个点一个编号，直接就是对称视图，图规模也从 m+n 点降到 n 点 | 加 **C5-U（单部图 Rabbit）**；二部图版保留为 B-Neutron-ref 的同源对照 |
| C6 超图划分 | ΣU_w 与 connectivity−1 只差常数，目标最直接 | **N2 下应升级**：Merkel 等报告 METIS 类方法在 GNN 训练中需要较多 epoch 摊薄（CPU、DGL、GCN 为 21–416 epoch），但在 200 epoch 的场景下可接受；C6 是唯一直接优化 U 的候选，划分后与 T(π′) 也最好解释 | 由**补充升为主候选**（待用户定）；成本照常报 |
| C7-I SLAWS 交集 | 与 C4 只换评分 | **N1 下有利**：交集评分偏好长行，划分后保留下来的正是长行，其收益不依赖短行，推测不会因支配项变化而蒸发【待核】。候选池问题同 C4 | 保留；随 C4 一起做候选池互换 |

**N1 的总体推测【待核，由 T1 的 Kendall τ 检验】：** 自带"恰好 W 行一组"的候选（C2–C7）在划分后受
成员平移损失更大；只输出平滑行序的候选（C1、Rabbit 序、§3 的 METIS 序、Gorder）受损较小。若成立，
成组类候选在划分后应改为"先删 D 再成组"（即 T(π′)），而这正是空白二要回答的问题。

## 3. 补查：GNN/幂律图重排方法

### 3.1 来源与筛选规则

主要依据 **Merkel 等，PVLDB 18(2) 2025**（旧调研 P21 只读了摘要）。本轮读了全文要点：12 种重排
（Table 1、§2.2.2）分五类，即 GAP 类（MINLA）、度数/hub 类（Degree Sort、Hub Sort、Hub Clustering、
SlashBurn）、窗口类（Gorder）、划分类（Rabbit、LDG、METIS）、带宽类（RCM、DFS、BFS）。

该文的度量是**端到端训练时间**，加速来自缓存命中，**不是 U_w**，因此它的名次不能直接搬来。
本稿只把它当作"在 GNN 图上值得测哪几类"的依据，筛选看两点：目标与 U_w 的关系；在对称视图下对 R 的作用。

该文可直接引用的事实：

- 划分类最好：Rabbit 平均 1.31×，METIS 1.22–1.33×（分区越多越好，k=65536 最高）。度数类平均
  0.97–0.99×，即基本无益（§4.1、图 3a）。
- 图的聚类系数与加速强相关（相关系数 >0.91），平均度数无关（§4.3）。
- gap profile、带宽等代理指标与加速的 Pearson 只有约 0.56–0.61（§4.6）。这支持本项目直接测 U/T，
  不用代理指标。
- 摊薄（§4.8，CPU、DGL）：Rabbit 对 GCN 需 2.9–16.7 epoch；METIS-1024 对 GCN 需 21–416 epoch。

### 3.2 建议新增或并入的候选

| 编号 | 方法 | 解决什么（阶段） | 与 U_w 的关系 | 接入与适配 | 出处 |
|---|---|---|---|---|---|
| **C8-METIS**【新】 | 图边割划分，k=⌈n/W⌉，分区按编号展平 | C 成组 | 边割把相连的点放进同一组。在社区结构强的图里，同组点的邻居大多在组内，U 被压低；但边割不等于 U，是代理目标 | 与 C6 构成**同一"划分"框架下只换目标**的一对（边割 vs 超图 connectivity），可按骨架 §4.2 第 1 条做单变量对比；METIS 远快于超图划分器。对称视图下同组点编号连续，推测对 R 也有利（交空白一核实）【待核】 | Merkel §4.1；Karypis & Kumar 1998 |
| **C9-Gorder**【新】 | 滑动窗口贪心，最大化 F(φ)=Σ S(u,v)，S = S_s + S_n | A 相似性 + C 排序 | S_s(u,v) = 共同入邻居数，在 A 对称时就是两行支持集的交，与 C7 的交集同源；但对窗口内**两两求和**，同一列会被多次计数（`candidates.md` §11 已指出此问题）。S_n = u、v 是否互为邻居（0/1/2） | 原文默认 w=5，需改为 w=W−1 作适配。**S_n 项在对称视图下与 R 直接相关**：u、v 相邻且编号相近，彼此作为列时就是连号。给 S_s、S_n 加权即可调节 U 与 R 的侧重，可作为 RQ2"考虑 R 的成组"的现成候选。代价 O(Σ_u d_O(u)²)，hub 处理：出度 >√n 的点跳过其出邻居的更新 | Wei 等 SIGMOD 2016 §2 式(1)–(3)、§3.2 定理 3.4 |
| C5 的局部变体 | Acc-SpMM：Rabbit 式模块度树 → 沿 DFS，每步取与当前点共同邻居最多的未访问点 | C 排序（局部阶段） | 链式的共同邻居，相当于 w=1 的 Gorder S_s | 作为 C5 局部阶段的替换（anchor-Jaccard ↔ 共同邻居链），属阶段互换。原文窗口 8 行，用 MeanNNZTC 度量，报告平均比 DTC-LSH 高 1.28×、比 Rabbit 高 1.10×；原文未报重排耗时 | Acc-SpMM（PPoPP 2025）§3.2、算法 1、§4.3.1 |

### 3.3 不进 RQ1 候选、转交其他调研块

| 方法 | 去向 | 理由 |
|---|---|---|
| BP 递归二分（Dhulipala 等 KDD 2016） | 空白一 | 目标是邻接表中邻居编号的 log-gap（BiMLogA），也就是让"一行用到的列"编号挨在一起，对准的是 R 而不是 U。每次二分按代价 Σ_q [deg₁·log(n₁/(deg₁+1)) + deg₂·log(n₂/(deg₂+1))] 交换顶点（§3.1、§4）。值得注意：若把"窗口"当作查询顶点，它可直接优化窗口级 R【新，待推导】 |
| RCM / BFS / DFS | 空白一（廉价排序基线候选） | 带宽类排序。对带状有限元矩阵（dawson5、olafu）可能同时压低 U 与 R；在幂律图上 Merkel 报告其收益居中 |
| Degree Sort / Hub Sort / Hub Clustering / SlashBurn | 空白二 | 在 GNN 训练中基本无益（Merkel §4.1），但**按度数排序会让 nz_r ≤ τ 的行聚在一起**，删去后剩余行的窗口不发生平移。这正是"重排时考虑划分"的最简单形式，可作空白二的基线 |
| N:M 导向的图重排（PPoPP 2025） | 不纳入 | 目标是满足 V:N:M 结构化稀疏的硬件约束，不是列并集 |
| HR-SpMM（ICS 2025） | 不纳入 RQ1；**可供 motivation 引用** | 没有重排，只按行长把行分给 TC 与 CUDA core（§4.1、算法 1）。这是又一个"按单行长度划分"的实例，与 motivation 批评的判据同型 |
| IO-aware GNN layers（ICML 2026） | 不纳入 | 只用 METIS 做缓存局部性的对照，没有新方法 |

## 4. 高优先级待读：Ascend-SpMM（arXiv 2611.01936，2026-11-01）

- 作者：Jiahe Wang、Yingxia Shao、Shuhan Wang、Qingbo Ge、Hongzheng Li、Yucheng Zhang。
- 摘要要点（本稿转述，未读正文）：面向昇腾 NPU 的 SpMM；以访存为中心的代价模型衡量每类工作与硬件单元
  的匹配度；**按密度把稠密区域分给 Cube、稀疏余量分给 Vector**，并给出两者冲突的理论界；子核做层次化
  流水与环形缓冲；对每张矩阵最强 NPU 基线几何平均加速 12.70–20.55×，GNN 端到端训练最高 6.8×；代码已开源。
- **为什么是第四象限问题：** 它与 NeutronSparse 同属"昇腾上的 Cube/Vector 分流"，又在 NeutronSparse
  之后出现。若它的"密度感知映射"已经按区域或窗口（而非单行长度）划分，motivation 批评的对象就要从
  NeutronSparse 扩到它，创新点 1 也要重新划界；若它比较了 NeutronSparse，则多了一组可引用的基线数字。
- **须从正文核对：** 映射的单位（行、窗口还是 tile）与密度判据；代价模型是否含 B 的供数（U、段数）；
  有无行重排；是否与 NeutronSparse 比较；数据集。
- 撰写本节时 arXiv 正文被限流；随后用户上传全文，已读，见上述讨论记录。
