更新日期：2026-11-03

## 1. 项目是什么

用户是研究生，研究 Ascend 910B NPU 上的 SpMM（稀疏矩阵 × 稠密矩阵）。起点是把 GPU 上的 RSH-SpMM 迁移到 NPU，主要对照 NeutronSparse（已经在 910B 上做 AIC/AIV 混合执行的工作）。

目前的状态：

- 旧的设备实验（E0–E2）已经暂停。
- 研究路线改成自顶向下、逐层推进，当前在第一层（行重排的结构实验，纯 CPU）。
- 最近的讨论重新审视了 motivation，形成了修订后的流程和一份代办清单，还有几个问题没讨论完。

## 4. 讨论是怎么走到现在的

1. **初始评审（11-02）**：上一个 AI 读完路线后，提了 7 条调整意见。见 `01`。
2. **motivation 动摇**：用户重读 NeutronSparse 后发现，它是按单行、单列抽取的，不是粗粒度地切分整个矩阵。这样，"迁移 RSH 去解决粗粒度划分问题"这个 motivation 就不够了。讨论后得出新的说法：NeutronSparse 的判据 Len ≤ α·K 只看一行自身的长度，而且划分和成窗是分开做的；在 NPU 上，应该按"这一行对所在窗口列并集的增量"来决定它的去向。用户同意这个说法。可以用 G1 实验验证。见 `02`。
3. **ND2NZ 能不能当创新点**：结论是它单独不够，因为它只减少搬运指令数，不减少字节数。真正值得研究的是列怎么排，让 B 的行连成段。这一条与第 2 条合起来构成**创新点**（"面向 NPU 的 B 供数代价，协同设计划分和布局"），**不是 motivation**——"B 的供数代价"是本项目在 E4 中衍生出来的新代价项，现有工作没有建模它不构成对它们的批评。motivation 只含第 2 条。可以用 G2 微基准验证创新点的成立条件（G2 为否不动摇 motivation）。见 `03` 与 `讨论记录/2026-11-04/2026-11-04-1521-motivation与创新点的边界更正.md`。用户的理解是"从目的出发，不从方法出发"。
4. **审查已有调研**：调研的思路是对的。分歧有三处：第一层的评价条件和最终结构不一致；首轮候选多，而且有些跨了层；连续列段只被当作观察项。其中第三处用户已经同意。见 `04`。
5. **存储层**：类 RS-tile 格式拆成"结构"和"载荷"两部分。用户确认，他之前说的 Bitmap 指的是载荷。在 910B 上，AIC 不能直接解码 Bitmap，所以离线预排的 Dense-NZ 载荷值得一试，已列为代办 E3-ext。见 `05`。
6. **修订流程和代办**：分层结构保留。新增统一代价模型，列置换升为正式变量，ND2NZ 降为一个执行选项。流程图、判断树和代办 T1–T10 见 `06`。
7. **未完成**：最后一轮有 6 个问题，其中第 1、2、5 点还没回答，因为当时的回复被系统中断了。见 `07`。

## 6. 容易弄错的事实

- **L0C 容量**：E0 实测 910B2 的 L0C 是 131072 B（128 KB），NeutronSparse 论文写的是 256 KB。按双缓冲算，M=128 时 N 最大只能到 128。
- **AIV 到 AIC 的数据路径**：CANN 9.0.0 中，UB→L1 的接口实际走的是 UB→GM→L1（依赖 TPipe/KFC），不是片上直达。
- **E0 直装**：预排布的 A 从 GM 直装到 L0A，已在小尺寸（M16）下验证了正确性，但没有性能数据。
- **E3 结果**：用户提供的 E3 r7 结论（Bitmap 和 Index 各有胜负，Dense16 几何平均仍有优势）在 `05` 里有摘录，当前分支里没有 E3 的原始数据，可能在远端的 `codex/*e3*` 分支上，需要向用户确认。
- **RSH Algorithm 1**：一次扫描同时输出窗口集合 W 和残余集合 C。不要说划分和成窗"需要合并"，用户的大纲本来就是这样写的。
- **判据方向**：RSH 把"Δ 小且 nnz 少"的行送到残余路径。按 NPU 的代价，这个方向可能反了，要通过实验确定。
- **第一层程序**：默认 `weighted-alpha=0`，相当于普通 Jaccard，而论文要求 α>0。Rabbit 和 Neutron 目前只是启发式近似，不是原论文算法的复现。

## 7. 和用户合作的方式

- 用中文交流。用户习惯逐条讨论，常常要求先复述理解，确认后再展开。
- 要客观审查。有分歧就直接提出来，不要为了用上已有材料而勉强解释，也不要把自己的假设当成结论。说错了直接承认并改正。
- 判断要有出处：论文的章节号、仓库里的文件、实测数字。拿不准的要标明是推测。
- 遵守 `rsh-npu-experiments/AGENTS.md`：规划方不擅自启动实例或设备实验，失败、中断、未测都要如实区分。
- 之前的会话多次被系统安全检查误中断。遇到这种情况，建议用户拆成更小的问题，分开问。

## 8. 上传 GitHub 前要注意

- `rsh-npu-experiments/` 是一个独立的 git 仓库，有自己的远端 `github.com/pangxiegonghhh/rsh-npu-experiments`，体积约 870 MB。如果在外层直接 `git add`，它只会被记录成一个指向子仓库的条目，里面的文件不会被上传。可以选的做法有：
    1. 外层只上传 README、讨论记录、调研和论文，实验仓库给出链接和分支名。
    2. 把实验仓库作为 submodule 加进来。
- `文献pdf/` 里是论文的 arXiv 版本。仓库如果是公开的，建议只放链接，不放 PDF。
- 外层建议加一个 `.gitignore`，忽略 `.DS_Store`。
