## B1 合成段间距：随机对等距

**① 问题。** 原阶段 3 合成网格的段间距是等距还是随机？若等距，ND2NZ 的合法合并会把「段数」这个自变量吃掉多少？对应计划阶段 3 的「段间距改成随机」那一条，下游是 **R 敏感性表能不能用于选路**，以及审核 §2.3 那个方向矛盾的解释。

**② 变量与取值。**

**阶段 0（读代码，不占设备，先做）**

- 从 M11 的合成生成器源码（`src/`、`recovered-evidence/src/`）读出 R1 / R4 / R16 / R64 四档段间距的实际取法。
- 对四档各报一张**实际段间距分布**（最小、p50、max、是否全等）。
- 报 ND 路径在四档上的**实际 API 次数与段片数之比**（合并率）。原始数据已有：阶段 3 的 `api_calls` 只计 B 的 DataCopy。
- **分岔**：四档全为等距 → 做下面的设备补测；已是随机 → **设备部分取消**，只把分布与合并率补进重算单的 R11，并在审核记录 §2.2 结案。

**阶段 1（设备，仅在阶段 0 判「等距」时做）**

| 项 | 取值 |
|---|---|
| 自变量：段间距排法 | `equi-gap`（等距，复用原生成规则，**同批次重跑，不引用原数**）、`random-gap`（计划原意，间距随机）、`hole`（极端非等距：一个大洞 + 其余紧邻） |
| 自变量：段数 R | 4、16、**32**、64（U = 64 固定；R=32 同时服务 B2） |
| N | 128、256 |
| 精度 | FP16、FP32 |
| 缓存档 | **只做 hot** |
| 路径 | p0 ND、p1 按行、p2 按条，三条都跑 |
| 重复 | 20 个随机区组，丢首次，首尾哨兵 |

点数：3 排法 × 4 R × 2 N × 2 精度 × 3 路径 = **144 点 × 20 = 2,880 条**。

**只做 hot 的理由**：审核 §2.5 发现按行路径在 cold 与 hot 下耗时到小数点后四位相同（FP32-n128 两档都是 7.2429），cold 档对该路径没有判别力；§2.6 又发现 hot 档 ND 基线被某个与 N、精度无关的量钉住。**在重算单 R4、R5 回答清楚这两条之前，加 cold 档只会把两个未解释的效应叠进来。** 若 R4 证明 cold 对按行确有判别力，再把 cold 作为 B1 的续项加上（点数翻倍，约 +1 小时）。

**③ 内核。** 复用 K-H 与 K-D，**一行不改**；只换合成输入。`kernel_version` 必须与 M11 阶段 3 的同一个 sha256 前 12 位，若不同则在 README 写明差异。共享 gmax 沿用 M11 的设定，**不做逐路径 g 调优**（那是另一件事，见 §末「不在本计划内」）。

**④ 计时。** 沿用 M11 阶段 3 规程：20 随机区组、丢首次、块首尾同载荷哨兵、核内计时、漂移 > 5% 整块作废重跑。**哨兵的 5 条单值要保留**（M11 阶段 3 只留了中位数与漂移）。

**⑤ 正确性（计时前）。** 三种排法 × 三条路径算出的 C 必须与 CPU 参考逐位相同；并用 M11 那套强地址编码（满秩非对称循环置换 A、B 前 11 特征编码 33 bit 源行、每 tile 独立输出）**在计时前**过一遍。任一不过，该格不计时。

**⑥ 预登记读法（跑之前写死）。**

主判据：同 R、同 N、同精度、同 hot 档下，**ND 在 `random-gap` 与 `equi-gap` 的耗时比** r_ND = T(random) / T(equi)。

| 结果 | 条件 | 去处 |
|---|---|---|
| 等距确有合并红利 | r_ND 的 95% 置信下界 ≥ 1.10，且在多数（≥ 5/8 的 R×N 格，固定精度分别判）成立 | **原 R 敏感性表作废**，以 `random-gap` 重画；审核 §2.3 的方向矛盾判为「由等距合并解释」；计划阶段 3 的「段间距改成随机」标为已落实 |
| 等距无红利 | r_ND 的 95% 置信区间落在 [0.97, 1.03] 内 | 原表可用；§2.3 的矛盾**另找原因**，并把「合成与回放不可互推」作为备选结论交 B2 判 |
| 说不清 | 其余 | 两张表并列报，不取舍 |

**内置一致性对照（这项的真正价值所在）**：按行路径的 API 次数等于补齐行数，与段结构无关，所以 **p1 在三种排法下应当几乎不变**。

| 观察 | 结论 |
|---|---|
| p1 在三种排法间的极差 ≤ 5% | 实现正确，「按行与段数无关」这句话站得住 |
| p1 的极差 > 5% | **段结构漏进了按行路径**，M11 按行侧的全部结论需复查，停下报告用户 |

**⑦ 工作量。** 阶段 0 半天（读代码，不占设备）；设备 1–2 小时；整理半天。

**⑧ 限定。** 只有 hot 档、只有 U=64、只有合成数据；`hole` 排法是人造极端，不代表任何真实矩阵；间距的随机分布由生成器定，换分布结论会变，分布与种子必须记进 `inputs.csv`。

## B2 用 Cora B1 的真实 (U, R) 打通合成与回放

**① 问题。** 合成网格能不能用来预测真实矩阵的选路？对应审核 §2.3。

事实：Cora B1 每窗 U = 35.5、R = 17.2、平均段长 2.06、R/U = 0.485；B0 每窗 U = 56.4、R = 50.4、段长 1.12、R/U = 0.894。而合成网格 U=64 的四档 R/U 是 0.016 / 0.063 / 0.25 / 1.0——**B1 的真实工作点落在 R16 与 R64 之间的空档里**，正是曲线翻转的那一段。

**② 变量与取值。**

| 项 | 取值 |
|---|---|
| 自变量：(U, R) 对 | **(36, 18)** 对齐 B1 的真实每窗均值；**(56, 50)** 对齐 B0；(64, 32) 保持与原 U64 网格可比 |
| 段间距 | `random-gap`（用 B1 阶段 0 / 阶段 1 确定的生成器）；另加一档按 **Cora B1 的实际段间距分布**抽样（记作 `cora-like`） |
| N | 128、256 |
| 精度 | FP16、FP32 |
| 缓存档 | 只做 hot（同 B1 的理由） |
| 路径 | 三条 |
| 重复 | 20 区组 |

点数：3 组 (U,R) × 2 排法 × 2 N × 2 精度 × 3 路径 = **72 点 × 20 = 1,440 条**。

**③ 内核。** 同 B1，不改。

**④⑤** 同 B1（正确性门在计时前）。

**⑥ 预登记读法。** 比较合成点 (36, 18, `cora-like`) 的按行/ND 比值与 **Cora B1 回放同格（hot）**的比值，记相对偏差 d = |比值_合成 − 比值_回放| / 比值_回放。

| 结果 | 条件 | 去处 |
|---|---|---|
| 可互推 | d ≤ 15%，在 4 个 hot 高 N 格（N128/256 × 两精度）中 ≥ 3 格成立 | 合成网格可用于表达选路；R 敏感性表（以 B1 为准的那一版）可进下游 |
| 不可互推 | d > 30%，在 ≥ 2 格成立 | **合成网格只能用于机制探查，不得用于选路**；M11 报告里凡用合成 R 表论证选路的句子都要加这条限定 |
| 说不清 | 其余 | 如实报告，两者并列 |

15% 这条线直接沿用计划 M4 已登记的 `replay_error_max = 0.15`（预测与回放相差超过 15% 则模型不合格），不另造标准。**30% 是我定的【推】**，用来给「明确不可互推」一个下界，可在派发前改，改了写进 `thresholds.csv` 的 `changed` 列。

另固定报告一个数：**(56,50) 与 (36,18) 两点的按行/ND 比值之差**，它是「重排把结构从 B0 挪到 B1 之后，选路偏好有没有翻」的合成侧答案，与回放侧的 1.48 倍并列报。

**⑦ 工作量。** 生成器改 1 天（要按 Cora 实际段间距分布抽样）；设备 1–2 小时；整理半天。

**⑧ 限定。** U、R 用的是**每窗均值**，而真实分布右偏（B0 的 R_w p50 = 48、max = 149），均值点不能代表整张图；`cora-like` 只复制段间距的边缘分布，不复制段长与间距的联合结构。本项只回答「合成能不能预测回放」，不回答「哪条路径在任意矩阵上更好」。

## B3 转置与普通加载的差价，重做对照

**① 问题。** 转置加载比普通加载多花多少？对应计划阶段 2 的第二条（「这是新路径多出来的成本」），下游是三条供数路径的端到端成本能不能拆开算。

事实：M11 给的差价在 6 个格（2 精度 × 3 N）里全是 0.00055 ± 0.00002 μs，占 plain 的 0.6%–2.7%，**与搬运量完全无关**。报告已提醒两种 primitive 的输入解释不同，但没解释这个常数本身。

**② 变量与取值。** 改成**三路同载荷对照**，三者输入同一批数据、输出同一份 L0 内容：

| 装入方式 | 说明 |
|---|---|
| `plain-only` | 普通加载，不转置（若该方式单独不可产出合法 L0 布局，则记「不可单独成立」并在读法里按此处理） |
| `transpose` | 转置加载，一步到位 |
| `plain+explicit` | 普通加载 + 另发一条显式转置 |

| 项 | 取值 |
|---|---|
| 行数 h | 1、2、4、8、16 |
| N | 16、32、64、128、256 |
| 精度 | FP16、FP32 |
| 批量 | 64、256、1024、4096（按 batch 回归取斜率，同 M11 阶段 2） |
| 重复 | 20 区组 |

点数：3 方式 × 5 h × 5 N × 2 精度 × 4 批量 = **600 点 × 20 = 1,200 条**。单核、不流水，同 M11 阶段 2。

**③ 内核。** M11 阶段 2 的同一 binary 的 host check 模式，加 `plain+explicit` 一种；64 MiB 池、核内计时不变。

**④ 计时。** 每格按 T = c + k × batch 回归取 k，报 20 区组的斜率均值、SD、t(19) 95% CI 与逐区组 R²。

**⑤ 正确性（计时前）。** 三种方式产出的 L0 内容（或最终 C）必须一致；`plain-only` 若布局不合法，记录其不合法的具体表现，不得强行计时。

**⑥ 预登记读法。** 对差价 Δ = k(transpose) − k(plain-only)（以及 Δ' = k(plain+explicit) − k(plain-only)），在每个精度内把 Δ 对「搬运字节 = h × N × 元素字节」做线性回归，取斜率 s。

| 结果 | 条件 | 去处 |
|---|---|---|
| 差价随字节增长 | s 的 95% 置信下界 > 0，且 Δ 在 h=16、N=256 与 h=1、N=16 之间相差 ≥ 2 倍 | 差价可用于估算转置成本；把它写进计划 §4 M7 的系数表 |
| 差价是常数 | s 的置信区间含 0 | 判定该差价为**纯发射开销**；计划阶段 2 的「转置多出来的成本」改写成「本对照不能估算转置成本」，并在 M11 限定里加一条 |
| 说不清 | 其余 | 两种解释并列报，附完整回归 |

另固定报告：Δ 与 Δ' 的比。若 Δ' ≫ Δ，说明一步到位的转置加载确有收益，这个数是「为什么不用普通加载 + 显式转置」的直接答案。

**⑦ 工作量。** 内核加一种方式半天；设备 0.5–1 小时；整理半天。

**⑧ 限定。** 单核、不流水，不含双缓冲与 g 批量，所以差价是上界；`plain-only` 可能不是一条合法的端到端路径，其 k 只作参照；A 侧的原始列块链不在本项内（那是审核 §2.9 的 R9，走重算单）。
