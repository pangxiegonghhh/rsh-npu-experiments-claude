# M11 重算与追问单（2026-11-15）

**为什么有这份：** `claude/RSH-NPU-审核记录-20261115-M11数据.md` 把 M11 的问题分成三类。本单管**第一类（数据有、算的或写的不对）与第三类（真伪未定、要看原值才能分）**，全部**不占设备、不重跑、不新租实例**。第二类（设计漏项）走 `M11b-supplementary-experiment-plan-20261115.md`。

**开给谁：** M11 的执行方（或任何拿到 `m11-work/recovered-evidence/` 的人）。
**起草：** 规划方会话 `claude-opus-5`，2026-11-15。

**三条纪律：**

1. **原件不动。** `m11-evidence-complete.tar.gz`、`recovered-evidence/` 下的原始逐轮值、原 `analysis-output/` 一律只读。本单的产物写进**新目录** `analysis-recompute-20261115/`，不覆盖 `analysis-output/`（报告自己也警告过「再次复算会覆盖本地 analysis-output 与本报告」）。
2. **不删点。** 不按胜负、离群、R² 剔点；所有表的分母要和 `cases.csv` 对得上。
3. **分清事前与事后。** 预登记的 8 格 5/8 判据**保持原样不动**；本单里凡改分母、改子集、换统计量的，一律标 **【事后】**，不得用来替换主判读。

每项的写法：**要什么 → 用哪些数据 → 算式 → 输出成什么 → 验收**。

## 第一批（四项，最先做；前三项不解决，下游没法动）

### R1 把 μs/矩阵 的归一化写成公式

- **要什么。** 报告那句「全卡 makespan/(cycles×24) 的吞吐归一化」量纲对不上（makespan 已是时间，再除以 cycles×24 得不到 μs/矩阵）。审核 §2.4、§2.6 的核算都压在这个定义上。
- **用哪些数据。** `recovered-evidence/results-stage3-a0/` 的每核 begin/end 原时钟、`verify_raw_clocks.py`、`stage3-summary.csv`。
- **算式。** 把实际代码里的那一行写成公式，形如
  `μs/矩阵 = (max_core(end) − min_core(begin)) / 50 ticks·μs⁻¹ / (矩阵数 × ?)`，
  并说明：分母里的「矩阵数」是 170 个窗口、还是内层 batch、还是两者相乘；24 这个因子出现在哪一步、为什么。
- **输出。** 一页 MD，含公式 + **一个格的逐步数值示例**（建议用 `FP32-n256-cold` 的 ND 路径，取某一区组，从原时钟一路算到 12.5942）。
- **验收。** 示例算出的数与 `stage3-summary.csv` 的对应值相符到报告的位数。

### R2 FP16/N128 按行那一格的诊断（唯一的反向格）

- **要什么。** 审核 §2.4：用阶段 2 的单行代价反推，四格的预测是 4.42 / 4.99 / 4.97 / 7.64 μs，实测 12.83 / 7.18 / 7.24 / 7.29，三格落在 0.95–1.46 倍，**FP16/N128 单独偏 2.90 倍**；而且同精度同路径 N 从 128 翻到 256，按行耗时从 12.83 掉到 7.18（降 44%），违反单调。线头：按行的 `blockCount = N/c0`，这四格分别是 8 / 16 / 16 / 32，**慢的恰好是 blockCount = 8 的那格**，N16 的 FP32（blockCount = 2）比值 3.845 也很慢；但阶段 2 没有重现这个惩罚。
- **用哪些数据。** `results-stage3-a0/` 里该格（p1、FP16、N128、hot 与 cold、Cora B1）的 20 个区组逐轮值与每核 begin/end；`api_calls`、`bytes_moved`、实际描述符实参；同格 ND（p0）与同精度 N256（p1）的同口径值。
- **算式/要列的表。**

  | 列 | 说明 |
  |---|---|
  | 区组号、rep | 20 × 20 全列，不汇总 |
  | elapsed_ns、每核 begin/end | 原值 |
  | api_calls、bytes_moved | 实际值与预期值（预期按行 = 7280） |
  | blockCount / blockLen / srcStride / dstStride | 实际传给 DataCopy 的四个数 |

  再给三张并列：该格 vs 同精度 N256、vs 同 N 的 FP32、vs 阶段 2 同配置的单行斜率。
- **输出。** 一页 MD + 一个 CSV；并明确给出**一句判断**：这格是（a）测量/配置故障，（b）blockCount=8 的真实几何惩罚，还是（c）现有数据分不开。
- **验收。** 若判（b），须说明为什么阶段 2 的同一路径、同一 blockCount 没有出现同一惩罚；若判（a），该格从主判读里剔除并在 README 记偏离——**注意这会把 6/8 变成 6/7，预登记判据仍然满足，结论方向不变**。

### R3 冷热判别力：三条路径分别算

- **要什么。** 审核 §2.5：按行在 cold 与 hot 下耗时到小数点后四位相同（FP32-n128 两档都是 7.2429，差 0.0000），而 ND 在同一对比里差 1.55–1.66 μs（约 16%）。要判定是「按行真的被发射数钉死、cold 对它没有判别力」还是「cold 条件没作用到被搬的数据上」。
- **用哪些数据。** `stage3-summary.csv` 全部 216 配置、工作集审计记录、cold 的唯一选中行记录。
- **算式。** 对每条路径、每格算 `cold/hot = T(cold)/T(hot)`，附 10,000 次成对区组 bootstrap 的 95% CI（种子沿用 20261115）；另报每条路径在 cold 档的**实际访存字节与唯一行命中数**。
- **输出。** 一张 8 格 × 3 路径的表（比值 + CI），加一张 cold 档访存记录表。
- **验收。** 要能回答：按行路径在 cold 档**是否真的访问了 ≥ 4×L2 的唯一数据**。若是，则 cold/hot ≈ 1.000 是真效应，须在报告里写明「cold 格的降幅来自 ND 变慢，不是按行变快」；若否，三个 cold 格的 35.65%–42.07% 不能用，主结论改用 hot 格陈述（见 R4）。

### R4 主结论的 hot-only 敏感性分析【事后】

- **要什么。** 不改预登记判据，另给一版只用 hot 格的陈述，让主结论不依赖 cold 档的判别力。
- **用哪些数据。** 已有的 4 个 hot 高 N 格。
- **算式。** 同主表口径（ratio of means + 成对区组 bootstrap CI）。现成的数是：FP16-n256-hot 26.17%、FP32-n128-hot 25.35%、FP32-n256-hot 25.94% 三格过 20% 线，FP16-n128-hot 反向 −33.31%，即 **3/4**。
- **输出。** 一张 4 行表 + 一句话：「hot-only 下 3/4 格降幅 ≥ 25%，结论方向与主判读一致」。
- **验收。** 必须标【事后】，且**不得写成「预登记判据在 hot-only 下也满足」**——预登记的分母是 8 格，改分母就不是那个判据了。

### R5 ND 与按条路径的 B0/B1 加速比（完成「换路后重排还值多少」）

- **要什么。** 计划 M11 第 6 条要求固定报告「普通拷贝路径下重排前后的耗时比」，报告给了按行的 12 行（1.48 等）✓，但**没给 ND 与按条路径的同口径 B0/B1**，所以读者无法判断 1.48 倍是比 ND 高还是低。
- **用哪些数据。** `reordering-ratios.json`、`stage3-summary.csv`（阶段 3 的 216 点本就含 B0、B1 × 三路径）。
- **输出。** 把现有 12 行扩成 **12 行 × 3 路径**的一张表（B0/B1 加速比 + CI + B1 时间下降），并单独给一句：三条路径的重排收益谁高谁低。
- **验收。** 行数与 `cases.csv` 的 B0/B1 配对数对得上。

### R6 B0 的绝对耗时与按条的完整主表

- **要什么。** 主表只有 B1 的 ND 与按行两列；按条只有一句「约为 ND 的 9.38–12.90 倍」，B0 的绝对值完全没进报告。
- **输出。** 一张 **8 格 × 3 路径 × {B0, B1}** 的绝对耗时表（均值 ± SD、20 区组），按条的 9.38–12.90 倍逐格落实到数。
- **验收。** 与 R5 的比值表交叉对得上（B0/B1 加速比 = 两列相除）。

### R7 两条普通路径「固定单路径」的完整表

- **要什么。** 预登记是「取两种发法中较快的一种」，这没问题；但报告按格选优后只报选中的那条，读者容易把选优成绩当单路径成绩。报告自己也说了未作两选一的选择校正。
- **用哪些数据。** `paired-contrasts.json`（两条普通路径逐轮值已在内）。
- **输出。** 两张完整表：**若固定只用按行**、**若固定只用按条**，各 8 格的比值 + CI；再给一张「选优 vs 固定按行」的差。
- **验收。** 选优表的每格必须等于两张固定表中较小的那个。

### R8 R 敏感性表的完整版（含 cold 与实际段间距）

- **要什么。** 报告只给了 hot 的四行，cold 说「全值见图 3/JSON」；另外四档的**实际段间距**从未写出（这与补测计划 B1 阶段 0 是同一条，先做哪边都行，结果互通）。
- **输出。** R1/4/16/64 × N128/256 × 两精度 × hot/cold 的完整按行/ND 比值表 + CI；外加每档的实际段间距分布（最小 / p50 / max / 是否全等）与 ND 的合并率（API 次数 ÷ 段片数）。
- **验收。** 合并率这一列若在四档间差异很大，直接回答了审核 §2.2。

## 第三批（机制追问，用已有证据回答，答不了就写答不了）

### R9 hot 档 ND 基线被什么钉住

- **事实。** ND 的 hot 值在四个高 N 格是 9.6211 / 9.7085 / 9.7022 / 9.8398，跨两种精度、两个 N 只差 2%；cold 是 9.83 / 11.37 / 11.26 / 12.59，随 N 与精度正常增长。
- **要什么。** 用 `profiler/` 里这四格的 MTE2 / MTE1 / MMAD / 同步 / Scalar 占比，或 makespan 的构成，说明 hot 下被哪个环节钉住。
- **输出。** 四格的占比表 + 一句机制判断。**没有 PMU 证据就写「现有证据无法归因」**，不要猜。
- **为什么要。** hot 格的「降幅」解释依赖这条；否则读者会以为 hot 下 ND 成本也随 N 增长。

### R10 转置与普通加载差价的常数性

- **事实。** 六格（2 精度 × 3 N）全是 0.00055 ± 0.00002 μs，占 plain 的 0.6%–2.7%，与搬运量无关。
- **要什么。** 两种 primitive 的**实际输入解释与描述符实参**，并说明这个常数是不是纯发射开销。
- **输出。** 一张参数对照表 + 一句结论。若判定是纯发射开销，在 `micro-fits.json` 的派生表里把这两列标注「不可用于估算转置成本」。
- **注。** 真要把差价测准，走补测计划 B3；本项只要一个解释与一条标注。

### R11 A 链的描述符自证（排除标签对调）

- **事实。** FP16：ND 0.773–0.780、普通 0.1316–0.1345；FP32：ND 0.1378–0.1416、普通 0.7688–0.7738。**两个精度拿到的是同一对数值（≈0.78 与 ≈0.13），角色正好对调。** 阶段 2 的 ND copy / 按条 copy 在 N16 上也有同样的 0.73 / 0.12 互换——按条那组能用 `srcStride = N/c0 − 1` 自洽解释（FP16/N16 时 stride 0 退化成连续，便宜；FP32/N16 时 stride 1，贵），所以这类互换**不必然**是错位。但 A 链这组必须给同样的解释。
- **要什么。** 2 链 × 2 精度 的 `blockCount` / `blockLen` / `srcStride` / `dstStride` / `repeatTimes` / 搬运字节 / 转置处理单位，逐项列出，并对照 §1.5 那三条（512 字节小块；FP16 一个小块正好 16×16；FP32 两个小块并一个方块）。
- **输出。** 一张参数表 + 一句话：标签没有对调，差异由 c0 与小块几何解释；或者承认对调并重出 A 链结论。
- **为什么要。** 一旦标签对调，「FP32 普通链慢 5.5 倍」会整个反过来，而这条正是 §1.5 待核事实直接支撑的结论。

### R12 阶段 1 正确性门的逐格清单

- **事实。** 报告只给项数（主 B 198 项 PASS，1,104 = 198×3 + 510）。计划阶段 1 要求的是 3 路径 × 2 精度 × 3 N × 3 段长 = **54 格**，198 怎么来的拆不出来。
- **要什么。** `GATES-PASSED.json` 的逐项清单，映射到计划的 54 格；哪些格由 198 项覆盖、哪些格没覆盖。
- **输出。** 一张 54 行的覆盖表（覆盖 / 未覆盖 / 由哪几项覆盖）。
- **验收。** 未覆盖的格要么补上（不占设备，门是 host check 模式），要么在 README 记为偏离。
