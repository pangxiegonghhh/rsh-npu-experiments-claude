## 2. 项目是什么

这是将 RSH-SpMM 的行重排/成窗思想用于昇腾 NPU SpMM 的研究。A 是固定稀疏图邻接矩阵，B 是随层变化的稠密特征，计算 C=A×B。目标为 **910B2**，当前 SDK 为 **CANN 9.0.0**。

W=16 表示窗口16行；U_w 是窗口需要的 B 行数（A 的非空列并集大小）；R_w 是这些 B 行在编号上连成的连续段数；T 是补齐后 K=16 计算块数。第一层重排已收口，B0为原始序，B1为项目 RSH 参考序。第四层目前选稠密16×1列块存 A，零也存，不做 Bitmap 运行时解码。M11 检查普通拷贝在实际布局/最优实现下是否改变“降低段数”的价值，**不要预设 ND2NZ、普通拷贝或创新点必然成立**。

工作名称统一用：

|工作名称|对应 GitHub 仓库|本次用途|
|---|---|---|
|**AscendSPMM**|https://github.com/IDMG-Lab/Ascend-SpMM |M11必须核对的普通 B 拷贝、转置加载、FP32 A路径|
|**AscSPMM**|https://github.com/LfLab-AI/Ascend-NPU-SpMM |AIV打包与READY/ACK参考，主要服务M8|

URL中的连字符或 `NPU` 是仓库路径的一部分，不能据此再创造第三篇工作，也不要把这两个实现读反。

已完成的源码初查（必须自行复核，尚不是M11设备结论）：

- **B是按行发普通DataCopy**：`CopyInB1`遍历每个被选中的B行，每行发一次。
- FP16：`blockCount=N/16, blockLen=1, srcStride=0, dstStride=15`；FP32：`blockCount=N/8, blockLen=1, srcStride=0, dstStride=15`。普通DataCopy这些字段单位是32B，不能套用DataCopyPad的字节单位。
- B后续转置加载：`repeatTimes=N/16, srcStride=1`，FP32另设`dstFracGap=repeatTimes-1`。
- A的FP16路径是普通DataCopy；**FP32启用的A路径用Nd2NzParams**，随后转置加载设`dstGap=1`。不要把旁边注释的普通搬运代码当成启用实现。
- 草案“按列条=R×N/16”只可先当FP16的推导。**FP32基本搬运块为8个float，保持同一L1布局时可能是R×N/8，必须按实际地址映射与转置参数推导、验收，不能照抄N/16。** 同时区分原始R与跨16行tile切分后的有效段片数。
- 现有M4的B消费本身也有转置加载。因此“普通拷贝额外增加一次转置”不能预设；要比较两条路径实际所需的加载指令与参数。

作为区分，**AscSPMM** 的另一仓库为 `LfLab-AI/Ascend-NPU-SpMM`，已核对提交 `875515ab73c71bc1c72574ca97811d44eac33efb`。若M11需要讨论与M8的关系，再读：

- `sparse/spmm_1d/arch22/internal/spmm_1d_kernel_variant.inc`：`copy_b_selected_direct_to_l1`、`copy_b_pack_row_major_to_l1`、`run_aic`/`run_aiv`、READY/ACK。
- `sparse/spmm_1d/arch22/internal/spmm_1d_fp16_utils.h`：ND2NZ辅助函数。
- `sparse/spmm_1d/arch22/spmm_1d_kernel.cce`：workspace/direct变体入口。

### M4的关键已知事实

- M5确认`ndNum=1/2/4/8/16`中测试过的合法等长等间距合并可用；任意不等间距不能凭该结论一条合并。M11必须用随机段间距，并记录合并合法性，不引用旧M4耗时代替新对照。
- M4的FP32 A由host按C0=8的**预打包L0A布局**写GM，kernel用普通`LoadData(aa, ag, ap)`从GM直接装L0A，`repeatTimes=2`；FP32关闭HF32。它不是“原始16×1列块→普通GM/L1拷贝→转置加载”的同一路径。**它证明的是该预打包直装路径正确，不能据此断言M11的原列块普通搬运链已经验收。**
- M4 host用`got == CPU_reference`逐元素完全相等判定；输入和输出为有限、可精确表示的整数标记，不是一般随机浮点容差比较，也不是对任意NaN payload/负零的逐位语义证明。复核实际readback与gate，不夸大“逐位”。
- M4计时覆盖MTE2+MTE1+MMAD+同步/Scalar的内核内部区间，非纯MTE2管道busy；全卡makespan/完成窗口数是吞吐归一化，不能直接叫单核心指令延迟。
- Cora：B0 ΣU=9583、ΣR=8565；B1 ΣU=6035、ΣR=2927；各170个窗口。U和R一起改变，重排收益不能归因成纯R收益。

## 6. 按M11原稿执行，先正确性再计时

### 阶段0：CPU/源码审查，不占卡

输出一份有提交号、文件与行号的参数表：FP16/FP32的普通B拷贝、ND2NZ、普通/转置加载；按行与按列条各自实际API调用数及适用条件；回答M4的FP32 A问题。对CANN9本机头文件与官方文档交叉核验。

可读的官方CANN9基础搬运文档：
https://www.hiascend.com/doc_center/source/en/CANNCommunityEdition/900/API/ascendcopapi/atlasascendc_api_07_0103.html

用户原稿中部分旧`document/detail`链接目前可能仅返回网站外壳，不能当作已读到正文。需要时用官方`doc_center/source`入口或本机SDK头文件，并记录实际版本。不要用8.x/9.1行为替代9.0实机证据。

### 阶段1：正确性总门槛

- 三条B路径：ND2NZ、普通按行、普通按列条；同一批源B、行列表、A、最终C必须相同。
- 精度FP16/FP32，N=16/128/256，段长=1/4/16；另覆盖尾块、最大stride、零填充和重复使用缓冲。
- 独立原始行列表/CPU参考、精确输出或逐位比较（明确数据域与验证方式）、GM前后哨兵、输入不变。
- 失败先保存失败版本和输出，修复后重过全部门槛，不能带着错误跑性能，也不能把一个实现bug当“硬件做不到”。

### 阶段2：单核搬运与加载代价

- 普通搬运行数1…16，N=16/32/64/128/256，两种精度，单核、明确“不流水”的同步口径。
- 照M5做多批量/重复与拟合，但**行数变化同时改变字节数，斜率不能直接命名为纯固定指令开销**；补同字节不同调用数对照，或明确不可识别性。API调用数、汇编指令数和PMU数不能混用。
- 单独核对普通/转置加载的必要性和代价，不先假设“新路径多一条转置”。报告整个加载链差异。

### 阶段3：实际流水与Cora判据

- 复用M4的消费/队列/计时骨架，尽量只替换B供数路径；同一批次重跑ND2NZ对照。
- 合成：每窗U=64，R=1/4/16/64；N=16/128/256；两精度；hot/cold；段间距为固定seed的随机分布。先登记全部地址与段表，正确性通过才计时。
- Cora：原始B0、重排B1，各三路径，保持原始窗口序和独立段表；冷热工作集与实际分配字节分别报告，保留矩阵内复用，不能仅凭跨度把Cora叫“每次都冷”。
- 20个随机区组，首尾哨兵、核内计时、原始重复值全部保留。漂移作废保留记录并重跑，不能事后按胜负删点。
- FP32 A另加普通拷贝链与ND2NZ链的正确性/耗时对照，使用同一逻辑A，算清host预排与运行时转换的边界，别只对比两种不同预排数据。

### 原稿的主判读规则

以Cora **B1** 为准，普通两种发法取较快者，但要保存各自结果及选择方法：

- 比ND2NZ快20%以上，且N≥64的多数主配置如此：报告此前提受到动摇，给出适用范围，论文更改交用户处理。
- 差距在5%内或普通路径更慢：报告未获得普通路径优势。正确性失败时保持当前路线，但只能说候选实现未验收，不能作普遍性能结论。
- 只在部分精度/N/cache下更快：报告有条件优势，不强行归入全胜。
- 固定报告普通拷贝路径下 **B0/B1耗时比**，U/R同时变化的限制写明。
- 原阶段3主网格的高N为128/256，须在计时前写清“多数”的分母与严格多数条件；若补N64，扩展组另列，不事后改变主结论分母。交叉选择普通路径时保留两条配对CI，说明有无选择偏差；不要仅用最小均值宣称可信优势。
- 分别报告各路径的加速比、相对耗时下降百分比与单位，避免把speedup和降幅混写。
