# 第0层 · 代价模型

给第 1 层（置换的目标）、第 2 层（分流与选路）、第 5 层（供数）提供判据。代办 C1–C7 见 `架构与代办/架构与代办-第二版.md` §3。

## 1. 模型的结构

- **AIC**（每个窗口，取两条路径中较小的那个）：
  - 按行：a × 补齐行（补齐行 = 16T）
  - ND2NZ：b × 合并后的调用次数 + c × T
- **AIV**：取 B 行 + Vector 计算 + δ。**全部待测**（C2）。
- **目标**：两引擎 makespan。如果带宽共享（C3），改为总搬运量。

和 Ascend-SpMM 的区别：它用 B 的数据量建模（每个非空列 αN），我们实测在 N ≤ 256 范围内 AIC 代价跟条数走，不跟字节走；而且同样多的非空列，连续性不同，代价可以差好几倍。

## 2. 一阶系数（热档，事后核算）

| 系数 | 值 | 怎么来的 |
|---|---|---|
| a | 23.1–23.9 ns / 补齐行 | 按行路径总耗时 ÷ 补齐行；Cora、arxiv，B0/B1、FP16/32、N128/256 都稳定（Cora FP16/N128 为 30–42，异常） |
| b | 67–68 ns / ND 调用 | 每格用 B0、B1 两点解 `时间 = b×调用 + c×T`；Cora 与 arxiv 一致（arxiv FP32/N256 为 75） |
| c | 134–142 ns / 块 | 同上 |
| 分界 | ≈ 4.6 补齐行 / ND 调用 | 假设两条路径的 Cube 消费都是 c，则按行供数 ≈ 14.75 ns/行，67.5 ÷ 14.75 ≈ 4.6【推】 |

时间换算：`每核代价 = T_归一化 × 24 ÷ 次数`，T_归一化单位是「μs / 完整回放」。

**限定：** 只覆盖热档；N ≤ 256；测的是「真实 B 供数 + 固定稠密 A 消费」，不是完整 SpMM；每格只有两个点，单格检验不了拟合优度，靠两张图一致作交叉验证；20 个区组是同一次启动的技术重复。

## 3. M11 系列关键数（Cora，A0，W16，170 窗口）

| 量 | B0 | B1 | 比值 |
|---|---:|---:|---:|
| ΣU | 9,583 | 6,035 | 1.5879 |
| ΣR | 8,565 | 2,927 | 2.9262 |
| T | 681 | 455 | 1.4967 |
| 补齐行（16T） | 10,896 | 7,280 | 1.4967 |
| ND2NZ 调用（N128） | 4,947 | 2,481 | 1.9940 |

ogbn-arxiv（10,584 窗口）：ΣU 2,274,123 → 1,323,060；ΣR 2,264,053 → 817,161；T 147,107 → 87,591（比值 1.6795）；ND 调用 N128 1,544,329 → 643,542，N256 1,737,232 → 662,921。

**主要结论（详见 `M11c第三轮审核记录.md`）：**

- 按行路径的 B0/B1 加速比 ≈ 补齐行之比：Cora 1.48（预测 1.4967），arxiv 冷档 3/4 格偏差 ≤ 1%（FP16/N128 −5.7%）。
- ND 路径的 B0/B1：Cora 1.79–1.87，热档在两张图上都比 API 预测低 6%–7%；arxiv 冷档反而高 6.5%–10.7%。
- 固定 U、T 只改 R：ND 的耗时只随**调用次数**变（R4→R8 调用不变、耗时不变）；按行不随 R 变。
- 绝对耗时：按行在 Cora 上 6/8 格更快，在 arxiv 上 8/8 格更快（B1 快 1.66–2.11 倍）。真实图 B1 每次 ND 调用平均只覆盖 2.1–2.9 个补齐行，在分界 4.6 之下。
- 按条路径不符合任何条数模型（预测 2.71，实测 1.09–1.91），不建模。

## 4. 已结案的写作约束

- 单位写「μs / 完整回放」，不写「μs / 矩阵」。
- 不说「段数是供数成本的主因」；有代价的是合并后的调用次数，且只在 ND 路径上。
- 三条路径的 L1 布局只能写「最终输出逐位相同 + 共用同一条转置加载」。
- FP16/N128 按行排除在所有机制性结论之外（C5）。
