# 现状与创新点重议（2026-11-17）

**给所有接手的 agent：** 用户在 2026-11-17 决定**暂停推进，重新思考创新点**。本文件说明为什么暂停、手里有哪些站得住的事实、哪些设想已被数据否定或收窄、还有什么没测。**在用户给出新方向之前，不要主动推进 L1-2、L2-3 或任何设备实验，也不要替用户选方向。**

标注：【已验】有实测或本环境复算支撑；【推】规划方推断；【待测】没有数据。

---

## 1. 为什么暂停

第二版（2026-11-16 立项）的候选创新点是：「实测的条数代价模型 + 按窗口选择 B 的供数路径（按行 / ND2NZ）+ 面向可合并段的对称置换」，外层整窗分流沿用 Ascend-SpMM 的前缀框架。

其中「按窗口选路」和「为可合并段做置换」是新意的主体。两个 CPU 实验（Cora）显示它们的收益很小：

| 代办 | 问题 | 结果 |
|---|---|---|
| L2-3 | 用现有行序，按窗口选路比全走按行快多少 | **0.96%**（各种系数假设下 0.10%–2.46%） |
| L1-2 | 专门为「可合并段」做列置换后，能快多少 | **1.9%**（对称视图，局部搜索 30 万步已走平） |
| — | 理论上限：每个窗口的 B 行在块内完全连续 | 38.8%，但稀疏图上远远达不到 |

详细数据见 `第2层-分流/代办/L2-3/README.md`、`第1层-置换/代办/L1-2/README.md`。

## 2. 站得住的事实

| # | 事实 | 证据 | 限定 |
|---|---|---|---|
| F1 | **AIC 侧 B 供数的代价跟指令条数走，不跟字节走**：按行 ≈ 23.5 ns/补齐行；ND2NZ ≈ 67.5 ns/调用 + 140 ns/块。字节翻倍（N128→256、FP16→32），按行单价不变（23.1–23.9 ns） | 【已验】M11 系列，Cora、arxiv 两图一致；模型复现 Cora 实测，偏差 0.5%–1.6% | 热档；N ≤ 256；B 侧供数 + 固定稠密消费，不是完整 SpMM；b、c 每格两点解出 |
| F2 | **在真实图上，按行（普通拷贝）比 ND2NZ 快**：Cora 6/8 格，arxiv 8/8 格（重排后快 1.66–2.11 倍） | 【已验】M11、M11c | 同上；Cora 的 FP16/N128 按行有双峰异常 |
| F3 | **重排（降补齐行，即降块数 T）的收益可以精确预测**：按行路径的 B0/B1 加速比 ≈ 补齐行之比（Cora 1.48 对 1.497；arxiv 1.67 对 1.679，3/4 格偏差 ≤1%） | 【已验】两图 | 重排算法本身沿用 RSH，不是新算法 |
| F4 | **有代价的是合并后的 ND 调用次数，不是原始段数 R**：固定 U、T 时，R 从 4 涨到 8 而调用不变，耗时不变 | 【已验】M11c 固定 R 项 | 只在 ND 路径上；按行路径对 R 不敏感 |
| F5 | **段合并算法本身没什么可优化**：贪心在不细分段片时已最优；允许细分也只少 4.1% | 【已验】执行方离线核查（L5-1） | — |
| F6 | **Ascend-SpMM 的数据量模型漏了 16 行补齐**：用「非零数 ÷ AIC 代价」排序代替密度排序，约 10% 的窗口换边 | 【推】Cora，CPU 计算；AIV 侧代价按 Ascend-SpMM 的模型假设 | AIV 侧没测，换边后实际快多少不知道 |

## 3. 被否定或收窄的设想

| 设想 | 现在的判断 |
|---|---|
| 「降段数」是独立创新点 | 收窄：只在 ND 路径上有代价，而且计价单位是合并后的调用；真实图上按行更快，按行对段数不敏感 |
| 统一的「指令数 × 每条代价」框架 | 按条路径不符合（预测 2.71，实测 1.09–1.91）；只对按行、ND 两条成立 |
| 按窗口选供数路径（第一版的 G-1） | Cora 上约 1%，本身不足以成为创新点 |
| 为可合并段做对称置换 | Cora 上到 1.9% 就走平；稀疏图结构上难以同时满足各窗口【推】 |
| 第一版创新点 1：行粒度划分（ΔU_w） | 已放弃（拍板记录 2026-11-16）；T24 只好 3.97% |

## 4. 还没测、可能改变判断的

| 项 | 为什么重要 | 怎么测 |
|---|---|---|
| **稠密图**（reddit、ogbn-products） | Cora、arxiv 度低、邻居分散，是对段最不利的图；稠密图上窗口的列天然更集中，L2-3、L1-2 的结论可能不同 | CPU；脚本现成；数据不在本环境，需执行方或用户提供 |
| **C1：单次调用代价随段片高度 h、合并段数怎么变** | 38.8% 的上限、4.6 的分界都假设长调用与短调用同价；从未分开测过 | 设备 |
| **C2：AIV 侧代价**（取 B 行、Vector 计算、δ 按行还是按段） | 外层分流两边比大小，缺一边；F6 的换边是否真能省时间也取决于它 | 设备 |
| **C3：AIC 与 AIV 是否共享带宽** | 共享则目标函数从 makespan 变成总搬运量，「按数据分工」本身可能不划算 | 设备 |
| **C4：完整 SpMM 下 B 供数是否仍是最慢的一段** | F1、F2 都只在「供数 + 固定稠密消费」上测过 | 设备；完整内核未写 |

## 5. 可供重议的方向（规划方整理，只列依据与缺口，不作推荐）

| 方向 | 依据 | 缺什么 | 风险 |
|---|---|---|---|
| A. 以「NPU 上 AIC 供数按条数计价」为核心，修正 Ascend-SpMM 的代价模型，进而修正分流 | F1、F6 | C2（AIV 侧）、C4；修正后在完整 SpMM 上的实际收益 | 若收益只有几个百分点，贡献偏「测量与建模」 |
| B. 回到「可合并段 / 按窗口选路」，但转向稠密图 | 理论上限 38.8%；稀疏图是最坏情况 | 稠密图数据与 L2-3、L1-2 复跑；C1 | 稠密图上也可能推不动；GNN 常用图多为稀疏 |
| C. 供数实现：真实图上按行（普通拷贝）全面优于 ND2NZ，而 Ascend-SpMM、AscSpMM 都走 ND2NZ | F2 | C4；完整内核；FP16/N128 异常的机制（C5） | 偏工程实现；需要确认不是本实现的特例 |
| D. 以重排降块数 T 的「可精确预测的收益」作为系统中被量化验证的一环 | F3 | 与其他方向组合 | 重排本身沿用 RSH，单独不构成新意 |

各方向可以组合。选哪个、怎么组合，由用户决定。
