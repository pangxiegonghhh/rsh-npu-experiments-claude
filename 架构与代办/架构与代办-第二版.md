## 1. 总图

```
第0层 代价模型（单列，给第1、2、5层提供判据）
   │
第1层 置换（对称视图 P·A·Pᵀ）──造出小列并集 + 可合并的长段
   │
第3层 窗口（W=16）── 切成行窗口
   │
第2层 分流 ─ 外层：整窗分给 AIC / AIV（按代价比排序取前缀，两边均衡）
   │        └ 内层：给每个 AIC 窗口标记 B 供数路径（按行 / ND2NZ）
   │
第4层 存储 ─ AIC：稠密 W×1 列块；AIV：CSR
   │
第5层 供数 ─ A：DataCopy→L1→LoadDataWithTranspose→Mmad
   │        └ B：按第2层的标记走按行或 ND2NZ
   │
第6层 执行 ─ AIC 流水、AIV 核、写回、核间均衡（最后做）
```

层号沿用第一版；执行顺序是 1 → 3 → 2 → 4 → 5 → 6（第 3 层只是固定 W=16）。

| 层 | 内容 | 状态 |
|---|---|---|
| 0 代价模型 | AIC：按行 a×补齐行；ND b×调用次数 + c×T。AIV：取 B 行 + Vector 计算 + δ。目标：两引擎 makespan | a、b、c 有热档一阶值；AIV 侧全空 |
| 1 置换 | 行置换短名单已有；列置换在对称视图里做【定】；目标改为降第2层代价【定】 | 列置换未开始 |
| 2 分流 | 整窗分流【定】；内层路径标记 | 未设计，暂停中（见现状与创新点重议） |
| 3 窗口 | W=16【定】 | 定 |
| 4 存储 | AIC 稠密 W×1 列块（2026-11-12 定型）；AIV 用 CSR【定】 | 定 |
| 5 供数 | A 的装载方式【定】；B 按标记选路 | 合并规则待用户提供 |

## 2. 一阶系数（第0层的现状，热档，事后核算）

| 系数 | 值 | 含义 | 来源 |
|---|---|---|---|
| a | 23.1–23.9 ns / 补齐行 | 按行路径总代价，含 Cube 消费 | Cora + arxiv，跨 B0/B1、FP16/32、N128/256 |
| b | 67–68 ns / 调用（arxiv FP32/N256 为 75） | ND 每次调用的供数代价 | 每格 B0、B1 两点解两个未知数，两图一致 |
| c | 134–142 ns / 块 | 每个 16 行块的 Cube 侧代价 | 同上 |
| 分界 | ≈ 4.6 补齐行 / ND 调用 | 高于此值 ND 划算 | 由 a、b、c 推出；假设两条路径的 Cube 消费相同【推】 |

限定：只覆盖热档、N ≤ 256、B 侧供数 + 固定稠密 A 消费，不是完整 SpMM；FP16/N128 按行除外。

补充（2026-11-16，段合并规则核对后）：b 是混合平均值，Cora B1/N128 的调用里 70% 是单段（ndNum=1）、30% 是合并调用，两者是否同价没测过；ND 路径的补零行也要发调用（每个有补齐的 tile 一次），只是不按行计价。

## 3. 逐层代办

编号规则：`C` = 第0层，`L1`…`L6` = 各层。「关联」一栏写依赖或影响的其他层。第一版编号（T*）的去向见第 4 节。

### 第0层 代价模型

| 编号 | 代办 | 关联 | 方式 | 状态 |
|---|---|---|---|---|
| C1 | AIC 系数补全：冷档、N > 256（带宽可能开始起作用）、多点拟合检验 a/b/c，验证「两条路径 Cube 消费相同」的假设；**新增**：合并调用（ndNum>1）与单段调用是否同价（同 dtype/N、同有效字节），单次调用代价随段片高度 h 的变化 | 供给 L2-1、L2-2；分界值影响 L1-2 | 【设备】 | 有热档一阶值 |
| C2 | AIV 代价：取 B 行、Vector 计算、δ 按每行还是每段计；和 Ascend-SpMM 的 β·d·N 对照 | 供给 L2-1；若 δ 按段计，L1 置换对 AIV 也有收益；与 L2-5、L4（CSR）相关 | 【设备】 | 全空，**外层分流的最大缺口** |
| C3 | **风险 1：AIC 与 AIV 是否共享带宽。** 文献已查尽（第一版任务 3 H4）：三篇论文都没有「同时跑 vs 分别跑」的对照；Ascend-SpMM 写回微基准推算并行只兑现约 90%【推】。只能做实验：同一份 B 取数分别在 AIC 单跑、AIV 单跑、两边同时跑，B 大于 L2 | 决定 L2-1 的目标函数：独立 → makespan；共享 → 总搬运量（Cora 上混合分配比全交 AIC 多搬 25.6%） | 【设备】 | 未测 |
| C4 | **风险 2：完整 SpMM 下 B 供数是否仍是最慢的一段。** 文献旁证：Ascend-SpMM 在 mip1 上 AIC 的 MTE2 占比 94.6%、AIV 占比 93.4%（★ Table 4），但那是它的内核、它的长行矩阵。要实验：L6 内核出来前，先用 M 系列内核做「消费开 / 关」对照；内核出来后用 msprof 看各单元占比 | 前提性，影响 L2、L5 全部判据 | 【设备】 | 未测 |
| C5 | FP16/N128 按行异常：区组级双峰（B2′ 中约 5%，Cora 中约 32%），单价 30–42 ns 偏离 23.5。无 PMU 定不了机制 | L5：该配置是否改走 ND | 【设备】，需 PMU | 未定 |
| C6 | FP32/N256 的 ND 在 R16→R32 只多 2 次调用却慢 25%，原因未解 | 影响 C1 的 b 在 FP32/N256 上的可信度 | 【设备】 | 未定 |
| C7 | 合成输入与真实回放的单价对不上（Cora 每窗实际比合成模型高约 50%；B2′ 也没解释 25% 的差）。**标定系数只能用真实图回放** | 约束 C1、C2 的实验设计 | 设计约束 | 机制未定 |

### 第1层 置换

| 编号 | 代办 | 关联 | 方式 | 状态 |
|---|---|---|---|---|
| L1-1 | 列置换研究：在对称视图 P·A·Pᵀ 里做【定】，下一层 B 的行序自动对齐，不额外搬数据 | 依赖 L1-2 的目标 | 【CPU】 | 未开始 |

| L2-4 | 两条路径混用：同一核内窗口间切换按行和 ND 有无额外开销【定：放在第2层】 | 关联 L5、L6-1；测量属【设备】 | 设计 + 【设备】 | 未开始 |

### 第5层 供数

- A：DataCopy 进 L1 → LoadDataWithTranspose → Mmad【定】。
- B：按第2层的标记走按行或 ND2NZ。

| 编号 | 代办 | 关联 | 方式 | 状态 |
|---|---|---|---|---|
| L5-1 | **B 的段合并规则**：tile 内从左往右贪心，等高、等步长、目的连续、真实行与补零行不混、`步长×N ≤ 65535` 就合并。贪心在不细分段片时已最优；允许细分也只少 4.1%（B1/N128 2,481 → 2,379），提升空间在置换不在描述符 | 供给 L1-2、L2-2、L2-3、C1 | 文档核对 | **已核对**（2026-11-16，见 `第5层-供数/代办/L5-1/`） |
