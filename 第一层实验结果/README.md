# 第一层实验结果

本目录存放第 1 层（全局重排，纯 CPU 结构实验）的**结果数据与证据包**。与其他目录的分工：

| 目录 | 放什么 |
|---|---|
| `当前流程与代办列表/` | 当前状态：做到第几层、代办还剩什么（持续覆盖） |
| `讨论记录/` | 历史存档：某一轮怎么想的、依据和出处（只追加） |
| `第一层实验结果/` | **数据本身**：各矩阵的 metrics、JSON、SVG、输入哈希、证据包 |

## 为什么不放在 `rsh-reorder-results/` 旁边

封存归档 `github-20261030-new-rsh2NPU/rsh-npu-experiments/docs/rsh-row-reordering-20261030/`
下已有一个 `rsh-reorder-results/`，装的是 192×192 合成矩阵那一轮。但该目录整体在封存归档
内，`AGENTS.md` 与 `docs/PROJECT_HANDOFF.md` 要求**字节不变**，不得新增或改动文件。所以
后续新结果一律落在本目录，按「矩阵名-日期」建子目录。

## 子目录

| 子目录 | 矩阵 | 日期 | 状态 |
|---|---|---|---|
| `cora-pilot-20261104/` | cora（2708×2708、10556 nnz、170 窗口） | 2026-11-04 归档 | 已核验，8 个方法视图 correct 全 True |

合成矩阵那一轮（192×192、2462 nnz、12 窗口）仍在封存归档内，路径见上，**不复制到本目录**，
以免出现两份同源数据。

## 登记一份新结果时要做的事

1. 子目录命名 `<矩阵名>-<用途>-<YYYYMMDD>/`，把原始证据包与解包后的文件都放进去。
2. 目录内必须有 `核验记录.md`：记录包哈希、输入哈希与包内 `input-sha256.txt` 的比对、
   程序哈希与封存归档的比对、矩阵规模与 manifest 的一致性、`correct` 标志。
   **哈希比对不通过的结果不登记**，按失败记录并说明。
3. 在 `讨论记录/` 当日文件夹下写一份读数与结论记录，并据此更新
   `当前流程与代办列表/` 的两个 md。
4. 结果里带 `weighted_alpha = 0.0` 的，引用时必须标明其 `rsh` 行是启发式近似而非 RSH
   原论文算法的复现（属 T4）。

## 已知的跨矩阵差异（务必注意）

合成矩阵与 Cora 在两项关键幅度上差近一倍：列置换对段数 R 的降幅为 18%–26% vs 42%–44%；
窗口占用率 ρ 为 0.149–0.239 vs 0.0613–0.0924。**这些幅度强烈依赖矩阵，任何单张矩阵都不足
以定常数。** 引用具体数字时必须带上矩阵名。
