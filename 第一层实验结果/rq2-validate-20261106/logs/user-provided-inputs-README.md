# SuiteSparse 五个矩阵（2026-11-06 下载记录）

## 结论先说

你截图里的那行 `403 Forbidden / AccessDenied` **不是你的浏览器问题，也不是会话网络策略问题**。

所有 SuiteSparse 官方下载链接（`suitesparse-collection-website.herokuapp.com/MM/...`
和 `sparse.tamu.edu/MM/...`）都会 301 跳转到 `http://sparse-files.engr.tamu.edu/...`，
而**这台文件服务器目前对所有人返回 403**——连最老的 `HB/1138_bus.tar.gz` 也一样。
底层是 AmazonS3 桶的权限被收紧，属于 TAMU 侧的故障，与客户端无关。

因此本目录改用 **Tim Davis 在佛罗里达大学时期的原官方镜像**
`https://www.cise.ufl.edu/research/sparse/MM/...`（2011 年前 SuiteSparse 的官方站点，
不是第三方转载）取回了 4 个矩阵；`wiki-RfA` 因为 2014 年才收录、旧镜像没有，
改用同一份数据的上游 SNAP 原始数据重建为 Matrix Market 格式。

## wiki-RfA 的重建说明

SNAP 的 `wiki-RfA.txt.gz` 是每 5 行一条投票记录（`SRC`/`TGT`/`VOT`/`DAT`/`TXT`），
共 317,240 条。转成矩阵时做了三件与官方版本对齐的处理：

1. **跳过投票人为空的记录**（1661 条，账号被隐藏/注销）——不跳过会多出 926 条边；
2. **同一对用户的重复投票只保留最后一次**；
3. **保留这些空投票记录里出现过的用户名作为孤立节点**（3 个）——这是官方版本
   为 11,380 行而不是 11,377 行的原因。

处理完恰好得到 `11380 x 11380 / nnz=188077 / 非对称`，与官方声明完全吻合。
取值分布：`+1`（支持）、`-1`（反对）、`0`（中立），符合 RfA 投票语义。

> 说明：节点编号按用户名排序生成，与 SuiteSparse 官方包的编号**不保证一致**。
> 若你的实验依赖固定的行/列顺序，请以官方 tar.gz 为准；只关心谱、条件数、
> 求解器等与编号无关的性质时，这个文件与官方等价。
