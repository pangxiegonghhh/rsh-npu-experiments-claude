# 本目录说明

本目录是「现在做到哪了、手上还有什么代办」的**唯一权威版**。它和 `讨论记录/` 的分工：

| | `讨论记录/` | `当前流程与代办列表/` |
|---|---|---|
| 性质 | 历史存档，只追加，写完不改 | 当前状态，持续覆盖重写 |
| 记的是 | 某一轮怎么想的、依据和出处 | 现在到第几层、代办还剩什么 |
| 更新时机 | 每次讨论产生新结论 | 每次讨论或实验改变了状态 |

本目录有四个文件：`流程图.md`（论点、六层流程、判断树的权威版）、`代办清单.md`（全部代办的权威版）、`进度总览.md`（按层的导读：做到哪、有哪些代办、先做哪件；2026-11-12 新增，与前两者不一致时以前两者为准）、`新接手AI工作单.md`（给完全没接触过本项目的 AI：怎么读仓库、现在该做什么、哪些事不能自己决定；2026-11-13 新增，与前两者不一致时以前两者为准）。

**查当前进度和代办，只看本目录，不翻讨论记录。** 想知道某条代办或某层判断为什么是这样，
再从本目录的「出处」列回查对应的讨论记录文件。

## 维护规则

1. 做完一轮实验、或一轮讨论产生了新代办/改变了某条代办的状态，**必须**回来更新本目录的
   `流程图.md` 和/或 `代办清单.md`。这是收尾动作的一部分，不是可选项。
2. 本目录的文件直接整体覆盖重写，不保留历史版本——历史版本就是 `讨论记录/` 里对应的那
   一份。不要在本目录里堆积「-v2」「-旧」之类的文件。`新接手AI工作单.md` 同样是覆盖重写，
   文件名不带日期，只在文内记「最后更新」与基底树哈希。
3. 代办清单里每一行的「出处」必须指向 `讨论记录/` 下的具体文件（如 `06`、`08`），不能
   空着。没有出处的新代办，先补一份讨论记录再登记。
4. 本目录不记录推测、不记录进行中的论证——那些属于 `讨论记录/`。本目录只写**已经定下来
   的状态**。
5. 这两个文件不涉及任何设备实验的执行、不改变 `AGENTS.md` 所在仓库
   （`github-20261030-new-rsh2NPU/rsh-npu-experiments/`）里的任何约定；那边的冻结项、
   分支规则、收尾流程仍以其 `AGENTS.md`、`docs/PROJECT_HANDOFF.md`、
   `docs/e0-e6-experiments/resume.md` 为准。

## 讨论记录命名约定（自 2026-11-04 起，向前不回填）

- `讨论记录/` 下按日期新建文件夹，命名为 `YYYY-MM-DD`。
- 文件夹内的文件名加时间戳前缀，精确到分钟，格式 `YYYY-MM-DD-HHMM-主题.md`（不含秒）。
- 本约定适用于**此后新产生**的讨论记录；`2026-11-03-路线评审/` 整个文件夹（含
  2026-11-04 补写的 `08`）保持原有命名，不重命名、不迁移，避免破坏其内部的交叉引用。
